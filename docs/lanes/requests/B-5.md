## Notes / recommendation (B states a recommendation; Lane C decides)

1. **Do NOT change the existing `unused_floor_area` def shape.** `UnusedFloorAreaData.to_dict()` is
   validated live against the current contract by Lane C's `tests/contracts/test_wiring_contracts.py`
   (it builds the subject's `unused_floor_area` and calls `validate_parity_data_document`). B-11
   slice 2 deliberately left that `to_dict()` byte-identical so it keeps validating; the capture
   status lives in the separate `neighbor_floor_area.NeighborFloorAreaCapture.to_dict()`, not in the
   shared `existing_floor_area_input` (which is `additionalProperties:false`).
2. **Minimal vs rich.** B recommends shipping at least the `neighbors` array (option 1): it reuses the
   already-validated `unused_floor_area` def and immediately lets the study list each neighbour's
   "Not confirmed" row with its sourced input. The richer `neighbor_floor_area` capture record
   (option 2) is worth adding if the product wants the explicit `captured`/`not_recorded` label and
   the set-aside provenance surfaced (e.g. to show *why* a neighbour is "not recorded"); B recommends
   it but it is Lane C's call.
3. **Never a capacity.** Every neighbour row stays the owner-settled "Remaining development capacity:
   Not confirmed" / "Needs verified zoning-lot boundaries and existing zoning floor area."
   (D-090-R038) — no remaining-capacity number, allowance, FAR or subtraction, same const pins the
   subject row already carries. The capture carries only the EXISTING-floor-area input and the
   set-aside figures (an input, never a capacity).
4. **Neighbour set.** The neighbour set is the recorded touching lots (method in
   `neighbor_floor_area.NEIGHBOR_SET_METHOD`, recorded in
   `docs/research/neighbor-floor-area-2026-10-03.md`); a block-wide neighbour set stays an open B-11
   owner question. Lane C decides where the neighbour set is assembled in the study (as it does the
   subject's B-05 inputs).
