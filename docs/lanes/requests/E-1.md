# E-1: Bundle the results contract (and its referenced schemas) into the API package

| | |
|---|---|
| From lane | E |
| Owner of the file(s) | C (per OWNERSHIP.yaml) |
| Files | `services/api/scripts/sync_contract_schemas.py`, `services/api/app/_contract_schemas/v1/results.schema.json`, `services/api/app/_contract_schemas/v1/site_fact.schema.json`, `services/api/app/_contract_schemas/v1/study.schema.json` |
| Why | M1-27 / E-01: the drawing kit (`services/api/app/drawings/kit/`) validates every results document against `results.schema.json` before drawing (fail closed). That schema and the contracts it references (`common`, `site_fact`, `study`) are not in the runtime bundle `app._contract_schemas.v1`, so a non-editable install (web-e2e, production image) cannot load them; the kit then refuses with `schema_unavailable`. In a source checkout it reads `packages/contracts/schemas/v1` instead. |
| What is blocked | Nothing today (the kit is behind `LANE_E_ENABLED`, off, and unwired). Blocks serving drawings from an installed API (later E-01 wiring, E-03, E-04). |
| Proposed change | Add `results.schema.json`, `site_fact.schema.json` and `study.schema.json` to `SCHEMA_FILES` in `sync_contract_schemas.py`, run it, commit the byte-identical copies (the `contracts-schema-bundle` drift check then covers them). No kit change is needed: `app/drawings/kit/schema_source.py` prefers the bundle as soon as all four files are there. |
| State | open |
