# B-1: Carry each source's version status ("Out of date" / "Version unknown") in the site_fact and results contracts

| | |
|---|---|
| From lane | B |
| Owner of the file(s) | C (per OWNERSHIP.yaml: `packages/contracts/**`, hot files) |
| Files | `packages/contracts/schemas/v1/site_fact.schema.json`; `packages/contracts/schemas/v1/results.schema.json` (description only); regenerated `packages/contracts/generated/site_fact.ts`; bundled copies under `services/api/app/_contract_schemas/**` |
| Why | Queue B-06 (plan check C-7, data side: "Data versions shown and current"). Lane B now pins each source's version and applies the "Out of date" rule (`services/api/app/profile/data_versions.py`). The site_fact `source` object is closed (`additionalProperties: false`) and has no slot for the result, so the status cannot travel with the fact to Lane D (details), Lane E (report appendix) or `export_record.sources`. |
| What is blocked | Attaching the version status to each site fact (a later Lane B follow-up). Until then, consumers call `assess_data_versions(...)` directly. B-06's own tests do not need the change. |
| Proposed change | **1. site_fact (additive, contract 1.1.0).** Add an OPTIONAL `version_check` to `$defs/source`: `{"status": "current" \| "out_of_date" \| "version_unknown", "label": "Current" \| "Out of date" \| "Version unknown" (tied one-to-one to status), "latest_known_version": non_empty_string \| null, "latest_known_seen_at": date_time \| null, "latest_known_query_ref": non_empty_string \| null, "reason": non_empty_string}`, `additionalProperties: false`, all six keys required when present. Conditions: `current` or `out_of_date` require a non-null `dataset_version` and `latest_known_version`; `out_of_date` is the only status whose numbers take the results `exception_label` "Out of date". Append "1.1.0" to the `contract_version` enum. The producer shape is `SourceVersionStatus.to_dict()` minus the pin fields already in `source`. **2. results (description only, no shape change).** Extend the `out_of_date` description to cover "a source a fact uses is behind a newer published version (check C-7)". The reason then comes from `DataVersionReport.out_of_date_reason`, which already validates as `out_of_date_reason`. Lane C decides whether a behind source sets `results.out_of_date`, or only the per-row `exception_label` from `DataVersionReport.fact_exception_labels()`. |
