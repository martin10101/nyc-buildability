# Walkthrough — one complete request for 215-16 Northern Boulevard (BBL 4073340070)

Owner directive **D-090-R101** (2026-10-04): "Walk through one complete request for 215-16
Northern Boulevard using the existing test setup, and demonstrate it running." This record runs
the **real code** over the **recorded official city data** in the committed benchmark pack and
quotes every number from an actual output. No product code and no flag default was changed
(D-090-R102): the lane flags were enabled only inside the test process (the harness sets them in
its own `os.environ`; production `services/api/app/config.py` ships them unset).

- Branch: `task/walkthrough-215-16-northern-2026-10-04`
- Integration head: `09641f4e86562a5abfd9a0aec20585a60c5123cc` (PR #378 merged)

## 3. Zoning lot and the keep / remove choice

### Zoning-lot status (C-9)

The study carries the lot-selection statement verbatim (§1): **"Based on the lots you selected — the
app does not verify the zoning lot"** (`study_setup.json` → `lot_selection.statement`; the same
string is `LOT_SELECTION_STATEMENT` in `three_answers/engine.py:48` and appears in the results
document's `lot_selection_statement`). Recorded zoning-lot documents are **flagged, not read**: the
W2 "Recorded zoning-lot descriptions or mergers" flag points at ACRIS (flag only, P-2), and the
benchmark pack records the ACRIS zoning-lot description + certificate (documents dated 2016, recorded
2022 — `acris_master_*.json`). The app never interprets them.

### Existing-building keep / remove (D-06 slice 2 / A-03) — the engine does not consume it

- **The web captures the choice.** `apps/web/src/components/architect/ExistingBuildingStep.tsx`
  renders radios "Keep the existing building" / "Remove the existing building", stores
  `existing_building_plan: "keep" | "remove"` on the study option, and under "keep" asks for the
  existing zoning floor area ("Needed for: remaining capacity, keep / rebuild comparison."), accepting
  a DOB-filing/CO value or a stated assumption (never DOF/PLUTO building area). Pinned in
  `architect/__tests__/existing-building-step.test.tsx`.
- **The server engine does not take it.** `ThreeAnswerInputs`
  (`services/api/app/scenario/three_answers/inputs.py:71`) has **no** existing-floor-area,
  keep/remove, or demolition field (verified: `[f for f in fields if existing/keep/remov/demol] == []`).
  `generate_results` therefore cannot change its answer on "keep" vs "remove". The
  remaining-development-capacity slot is **always** `not_available`:

  ```json
  "remaining_floor_area": {"status": "not_available",
    "reason": "Needs verified zoning-lot boundaries and existing zoning floor area.",
    "reason_kind": "missing_input"}
  ```
  The UI renders this as **"Remaining development capacity: Not confirmed"** (D-090-R038; the exact
  reason line is pinned in `apps/web/e2e/development-limits.spec.ts` as
  `REMAINING_REASON = "Needs verified zoning-lot boundaries and existing zoning floor area."`). The
  literal phrase "remaining development capacity" never appears as a number anywhere in the document
  (verified: `"remaining development capacity" in json(doc).lower() == False`).

**Gap, named exactly:** the keep/remove choice and the existing zoning floor area are captured in the
web (`ExistingBuildingStep.tsx`) and surfaced as a site fact + a W2 flag, but `generate_results` /
`ThreeAnswerInputs` (`three_answers/inputs.py`, `engine.py`) do not consume them, so "keep" and
"remove" produce the identical result today and remaining capacity stays "Not confirmed". I did not
simulate the keep/remove difference, because the engine does not support it.

### Existing zoning floor area (B-05)

The benchmark pack records the existing building (DOB NOW job 440608941: 5-story new building, 38
units, `proposed_zoning_sqft 39934`; the competitor-review figure "about 54,488 sq ft" is recorded
*building* area, never subtracted). In the study the `existing_zoning_floor_area` fact is **unknown**
(no DOB rows were wired into the study provider), so the engine has nothing to subtract and correctly
leaves remaining capacity unconfirmed.
