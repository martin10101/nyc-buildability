## Ruling on the central question (rider c: removed 512-char cap)

The change removes `ENTERED_TITLE_ATTR_MAX_LEN = 512` and sets `const enteredTitle = enteredInput;` (`AddressConfirmCard.tsx:134`). `enteredTitle` flows only into two sinks: `title={enteredTitle}` and `aria-label={enteredTitle}` on a `<strong role="img">` (`:220`), alongside the visible text child `{enteredInput.trim()}` (`:221`).

### 1(a) XSS — SAFE
Both sinks are standard string attributes (`title`, `aria-label`) plus a text child. React escapes JSX attribute values and text children identically; a string can never break out into markup, script, or an event handler through these sinks.
- **No `dangerouslySetInnerHTML`** anywhere in `apps/web/src/` (grep at db445634; the only hits are a test assertion and the doc-comment in `bounded.ts:5`).
- **No URL/href/src sink** for reflected text: the only URL on this surface (ZoLa deep-link) is built exclusively from a re-validated canonical BBL via `zolaLotUrl(canonicalBbl)` (`AddressConfirmCard.tsx:82`, gated by `validateBblInput`), returning null (no link rendered) for anything non-canonical (`:36-51`). Reflected text can never reach an href.
- **No style sink.**
- Existing regression `address-resolution.test.tsx:661` ("script/markup in input_echo.street and grc_message renders as escaped text; nothing executes, nothing reaches an attribute") already pins this behavior. React's escaping is sufficient for both the attribute and text sinks here.

### 1(b) DoS/memory — BOUNDED upstream; acceptable, NOT a finding
`enteredInput` is **not** unbounded. Two real input paths, each bounded upstream:

1. **typedInput path** (architect autocomplete): `enteredInput = typedInput` when non-blank (`AddressConfirmCard.tsx:109-111`). `typedInput` originates from the autocomplete `text` state, which is bound to an `<input … maxLength={200}>` (`architect/AddressAutocomplete.tsx:170`); `choose()` passes that `text` to `onPick(item.query, text)` (`:116`), threaded via `AddressResolutionScreen.tsx:308-310 → runResolve(query, typedText) → result.typedInput`. **Bound = 200 chars** (`AddressAutocomplete.tsx:170`).
2. **input_echo fallback path**: `enteredInput` is built from `view.inputEcho.{houseNumber,street,borough,zip}` (`AddressConfirmCard.tsx:112-120`). Each field is produced by `textOrNull` (`address-api.ts:257-260`) → `boundedText(value, "")` with `max = MAX_REFLECTED_TEXT_LENGTH = 600` (`bounded.ts:20,35-51`), which also strips C0/C1 control chars and normalizes `\r\n\t`. **Bound = 600 chars/field.** Proven by the unit test `address-confirm.test.tsx:1182-1204` rendering a full 600-char entry with no truncation marker.

So the removed 512-cap was applied to a value already bounded to ≤200 (typed) or ≤600/field (echo). Removing it raises the worst-case attribute size from 512 to at most ~600 chars (single echo field) — or, in an adversarial four-field echo, ~2.4 KB. This is a single, small, **self-reflected, non-persisted** string that is already rendered at the same length as the adjacent visible text node; the attribute never carries **more** than the visible text (that equality is the honesty goal). ~0.6–2.4 KB in one attribute is not a memory/DoS vector, there is no cross-user amplification (the echo is the requesting user's own input, not stored and re-served to another tenant), and no loop/quadratic behavior. **Acceptable risk, not a finding.**

Named upstream bounds: `AddressAutocomplete.tsx:170` (`maxLength={200}`) and `bounded.ts:20` / `bounded.ts:35-51` via `address-api.ts:205-209,257-260` (600/field).

*Report-precision note (advisory G5-1):* the producer report §rider-c calls the visible text "ALREADY unbounded." That is imprecise — it is bounded upstream, not in the component. The security conclusion (attribute ≤ visible text; no XSS; negligible DoS) holds regardless.

Grep across `apps/web/src/components/address/` and `address-api.ts`/`record-address.ts` for `console.*`, `analytics`, `track(`, `Sentry`, `captureException`, `navigator.sendBeacon`, `fetch(` referencing the reflected value: **no match**. `enteredInput`/`enteredTitle` flow ONLY into the `title`/`aria-label` attributes and the visible text node (`AddressConfirmCard.tsx:204-221`). The confirm/remember action `rememberAddress(outcome)` (`:381`) does **not** persist `enteredInput`/`typedInput` — it stores a BBL-keyed label built from `inputEcho.houseNumber + canonical.streetNameNormalized + canonical.boroughName`, bounded to 260 chars, in **sessionStorage** (per-session, single-user) with graceful failure (`lib/architect/selected-address.ts:11-28`).
