## Method (same shape as accepted M3-T008 / M5-T163)

For each section: one direct HTTPS GET of the official HTML (`curl -A Mozilla/5.0`, host
`zoningresolution.planning.nyc.gov` only), the node id read from `data-content-nid`, then one GET of its
print/PDF render (`entityprint/pdf/node/<id>` → `print/pdf/node/<id>`). The `verbatim_excerpt` was
extracted PROGRAMMATICALLY from the raw HTML `sec-body`→`field--name-body` container (one block per
paragraph / list item; defined terms `<strong><em>` → `#term#` with the render's inner spacing; a
double line break `<br /><br />` splits a heading from its paragraph; embedded figures/images omitted;
whitespace normalised; no word changed). **List labels were taken from the official print/PDF** (the
M3-T008 G1 F1 lesson). Each excerpt was cross-checked block-by-block against the print/PDF text layer
(`pdftotext`); every block was found verbatim (hyphen/quote/whitespace tolerant). Tables are carried in a
structured `table`/`tables` field (caption, columns, a header-structure note, and the rows — every cell
verbatim with `#term#`) and replaced in the excerpt by `[table - see structured \`table\` field]`; every
cell was confirmed against the print/PDF. `content_digest_sha256 = sha256(verbatim_excerpt)`;
`extraction_status` extracted_draft; `raw_html_verified` false on every file. A pause of a few seconds
separated requests; every request returned HTTP 200; no refusal occurred.
