N1. launch.sh uses `set -u` (not `set -euo pipefail`). This is deliberate and defensible: step 4 runs `$NYC_SUP_GATE_CMD; gate_code=$?` to capture the gate's RAW exit (the shell-routing discipline), which `set -e` would abort; there are no pipelines, so `pipefail` is moot. Each critical step fails closed explicitly via `|| refuse`. Acceptable as-is; optionally add `set -o pipefail`/`set -f` for defence-in-depth, but not required.
N2. The unquoted `$NYC_SUP_GATE_CMD` / `exec $NYC_SUP_START_CMD` (SC2086-disabled) perform word-splitting + globbing of OWNER-configured, trusted systemd values. This is word-splitting, not `eval`: shell metacharacters (`;`, `|`, `$(...)`) are NOT interpreted, so there is no shell-injection path. Globbing of a stray `*` in a value is theoretically possible but the values are owner-authored config. No change required.
