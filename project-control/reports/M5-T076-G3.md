Every other call site in `post_max_envelope` is wrapped (`registry = _effective_registry()` at :329-333 and the engine call at :372-400 both end in `except Exception: return _internal_error_500(correlation_id)`). X-Correlation-ID: None
```
body: Internal Server Error
```

That violates `MAX_ENVELOPE_STATUS_STATE_MATRIX`'s `(500, "internal_error")` pair and the route's "X-Correlation-ID on every response" discipline. Fix: wrap the derivation hop in `try/except Exception` → `logger.error(... stage=derive_lot_geometry ...)` + `_internal_error_500(correlation_id)`, matching the two sibling guards.

**F2 — MAJOR — `services/api/app/api/v1/max_envelope_api.py:162-175` (`_should_derive_lot_geometry`): a malformed `lot.lot_line_segments` is silently replaced by derived geometry instead of refused.**

The guard is `if isinstance(segments, list) and len(segments) > 0: return False`. A non-list value falls through that check, so when a BBL is present the derivation runs anyway and line 359 (`lot = {**lot, "lot_line_segments": list(derived.segments)}`) overwrites the malformed field — suppressing the typed 422 that `_build_lot_context` raises today.

Reproduced from `services/api` (router mounted on a fresh `FastAPI()`, working rectangle provider injected via `mod.get_lot_geometry_provider`):

```
malformed segs + bbl    -> 200 None None            | placement: fitted
malformed segs, no bbl  -> 422 validation_error lot.lot_line_segments
null segs + bbl         -> 200 ...                  | placement: fitted
```

A body carrying `{"lot_line_segments": "abc"}` is a documented typed refusal today and becomes a 200 with a fitted candidate after this change. `_enforce_route_caps` (`max_envelope_api.py:235-256`) also skips non-list values, so nothing upstream catches it either. Fix: derive only when the field is absent, `None`, or an empty list; leave every other type on the typed-refusal path so the `lot.lot_line_segments must be an array` refusal survives.

**F5 through F8 (moderate and minor)**

**F5 — MODERATE — `lot_geometry_derivation.py:276-289`: the lazy production client is constructed inside the threadpool hop, reintroducing the DB-039(i) first-touch race the sibling route explicitly forbids.**

`_effective_lot_geometry_provider()` is correctly resolved on the event loop (`max_envelope_api.py:351`), but it returns a closure whose body runs `global _PRODUCTION_CLIENT; if _PRODUCTION_CLIENT is None: _PRODUCTION_CLIENT = ResilientMapPlutoGeometryClient()` — and that body executes inside `run_in_threadpool`. Two concurrent worker threads can both observe `None` and each construct a client. The constructor builds a `TTLCache`, a `CircuitBreaker`, an LKG `OrderedDict`, and a `ResilienceMetrics` (`mappluto_geometry_arcgis.py:1951-1994`), so the loser's cache, breaker state, and metrics are silently discarded and resilience state splits. `proposal_checks_api.py:218-220` states the rule verbatim for the registry: "this resolves the lazy global ON THE EVENT LOOP and MUST NOT be called inside a `run_in_threadpool` hop — a first-touch race between concurrent worker threads could otherwise load and cache the production registry twice." Fix: construct the client eagerly inside `production_lot_geometry_provider()` (which runs on the event loop), or guard the global with a module-level `threading.Lock`.
