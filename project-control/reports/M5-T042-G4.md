This is a sound design adaptation, not a defect — noted so a future reader isn't misled that the billing-endpoint-`[]` path is exercised.

2. **[ADVISORY] Error taxonomy / retry / 400-drift wiring has no per-connector regression test.** `_raise_for_unexpected_status` 400-classification (`dtm_condo_soda.py:365-386`), `_classify_400`/`_sanitize_error_code` (`:306-323`), the 429/timeout/unavailable surfacing (`:388-415`), and `_fetch_rows` non-JSON-200 / non-array / non-object-record drift raises (`:443-464`) are untested here. The packet explicitly scoped tests to C1-C7/C9/C10 and deferred C11-C14 (incl. rate-limit). Recommend the later wiring/live-era packet add these.

3. **[ADVISORY] Two `resolve()` unit-path branches untested:** unit-BBL-empty → UNRESOLVED (`dtm_condo_soda.py:654-662`) and unit-row-without-condo_key → return direct base lots without expansion (`:693-698`). 4. **[ADVISORY] C10 covers only the static column inventory, not runtime drift detection.** `test_c10_*` assert frozenset sizes (9/16) and fixture-key subset membership, but the runtime `unknown_columns` advisory note and `multiple_condo_numbers/keys` notes in `_collect_base_lots` (`dtm_condo_soda.py:484-505`) are never triggered by a test. Research §9 C10 envisioned drift *detection*; the module treats extra columns as advisory-only (fail-closed only on the load-bearing `condo_base_bbl`), which is reasonable but its note-path is unexercised.

5. **[ADVISORY] Cosmetic label:** `resolve_by_condo_key` sets `lot_class=LOT_CLASS_NOT_A_CONDO` on both its UNRESOLVED and RESOLVED results (`dtm_condo_soda.py:774,788`).
