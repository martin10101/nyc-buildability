## R124 CENTRAL ADJUDICATION — RULING: **PASS** (satisfied for this task's acceptance)

**Requirement (R124, verbatim):** "fix the M0-T045 G5 LOW-1 park-to-approve integrity issue — bind the forwarded prompt bytes to the OPERATOR-NAMED approval digest at approval time, with adversarial tests."

**Technical predicates I verified myself in code (not from any report):**

1. **The forwarded bytes are non-reproducible outside the journal — TRUE.** `build_forwarded_prompt` (`codex_reviewer.py:684`) appends `f"FORWARDED AT: {to_utc_iso()}\n"`, an ephemeral wall-clock stamp generated at park time and stored only in the journal `prompt` field. The parked/anchored bytes contain it: `loop.py:1764` parks `"prompt": forwarded_prompt` and `loop.py:1776` sets `"prompt_bytes_digest": digest_of(forwarded_prompt)`.
2. **The operator-named digest is the timestamp-free S13.5 instruction envelope — TRUE.** `--approve-prompt-digest` is checked only against `pending["digest"]` (`cli.py:1678`, `1689`), which is `prompt_digest = self.approval_digest_for(decision)` (`loop.py:1712`) = `approval_digest(...)` over `{task_id, stage, allowed_paths, requested_action, stop_conditions}` (`loop.py:550-569`) — explicitly "the instruction, not the clock." It does **not** cover the forwarded bytes.
3. **The park→approve LOW-1 window is closed — TRUE.** `approve_pending_prompt` (`loop.py:662-679`) now refuses fail-closed (`pending_prompt_unanchored` if no anchor; `pending_prompt_tampered` when `digest_of(prompt) != anchor`) and binds `approved_digest = anchor` — never a fresh re-hash of the (possibly tampered) current bytes. The CLI re-verifies before any transition and writes a sealed `operator_resume_pending_prompt_refused` audit event on mismatch. Resume re-checks `digest_of(prompt) != approved_digest` (`loop.py:2042`).
4. **Adversarial tests exist, are non-vacuous, and pass — TRUE (I ran and read them).** `test_tamper_between_park_and_approval_is_refused` (tampers only `prompt`, leaving anchor+digest intact → CLI exit 1, "byte anchor", no state change, sealed refusal, chain still verifies) and `test_tamper_after_approval_is_caught_at_resume` (legit approval, then tamper → `forwarded_prompt_unavailable`, `provider_calls == 0`). Plus happy-path byte-identity, blank/missing-digest, and 3 direct unit tests. All 8 pass.
5. **The original LOW-1 scoped a single-field tamper and excluded the journal-write-forgery class — TRUE.** `M0-T045-g5-security.md` LOW-1: "an attacker WITH JOURNAL WRITE who tampers the `prompt` field between park and approval… Same access already forges checkpoints/decisions/flags — no new privilege escalation."

**Ruling and construction.** R124 is **satisfied for acceptance.** The literal construction — "operator names `digest_of(forwarded bytes)`" — is **impossible to implement more strongly**: because the forwarded bytes carry the ephemeral FORWARDED-AT stamp (predicate 1), the operator cannot compute that digest independently and would have to read it from the very journal an attacker with write access controls, so it is no stronger than a journal-resident anchor. The implemented design is the strongest honest construction: the operator names the **reproducible, timestamp-free instruction digest** (what is actually being authorized), while the exact timestamped bytes are **byte-anchored at park when authentic** and fail-closed-verified at approval and resume — which is in fact *stronger* than "operator reads bytes at approval," since the anchor is frozen before any post-park tamper. This closes exactly the LOW-1 window (predicates 3–4). The irreducible residual — a two-field forgery rewriting `prompt` **and** `prompt_bytes_digest` consistently — is the **same excluded class** the original LOW-1 carved out (predicate 5: the identical journal-write capability already forges approvals/checkpoints/decisions directly; no new escalation; SHADOW-ONLY forwards nothing). That residual is tracked as **G5 C2**, a pre-**activation** item to be surfaced verbatim in the owner's activation decision line or closed before supervised-auto — i.e. an R131/R132 concern, **not** a blocker to this SHADOW-ONLY task's acceptance. R124's own source (am.12) targets "the M0-T045 G5 LOW-1 park→approve integrity issue," and that issue is fixed with adversarial tests. **No producer rework and no owner decision are required for acceptance of R124**; the C2 residual is an owner decision required only before activation.
