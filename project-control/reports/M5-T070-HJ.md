**(3) The gap experience — legible and honest.** The token-to-copy map (`GAP_REASON_COPY`, :56-66) covers all four real `EnvelopeGapReason` values, an unknown token renders verbatim rather than inventing copy, and the server's human prose renders directly below. That is the right stance. The headline phrase "this massing dimension" is engineer-speak an architect will not parse on first read, but the detail line rescues it. No finding beyond wording (finding 10).

**(4) The production-reachable state — comprehensible only partway.** Two production-reachable states exist, and the *more* reachable one was not the one I was pointed at. ## Part 3 — Findings (all ADVISORY; none blocks this gate)

**1. HIGH — A split-zoned lot silently loses its zoning district, and the analyst is never told.** `maxEnvelopeRequestForProfile` (`max-envelope-api.ts:534-537`) sends `zoning_district` only when `districts.length === 1`; for two or more it sends `lot_rule_facts: {}`. The engineering is right — never guess which district governs — and it is tested (`max-envelope-api.test.ts:395-398`). But nothing on screen discloses it. On a split-zoned lot the analyst will see gaps whose server prose reads "no applicable rule was found for this dimension" and will reasonably conclude the platform has no rule for their district, when in fact this surface chose not to send it. That is misleading by omission, and it sits against the frontend rule "never silently apply a default that materially changes a scenario." Needs one sentence in the panel when the profile carries 2+ districts. **This is my top rider for the mount seam.**

**2.** Adoption gives a sighted analyst no visible feedback at all — the panel does not change, both announcers are visually hidden, and the reseeded table is below the fold; add a visible confirmation and move focus to the editor heading.

**3.** Clicking Adopt a second time silently replaces the working draft and discards all manual edits, with no warning, label change, or undo (converges with G3 advisory 4).

**4.** Duplicate announcements: the failure card is `role="alert"` rendering the identical string the polite announcer already holds, and the aggregate is `role="status"` for the same load event — both break the exactly-once invariant documented in `OutcomeAnnouncer.tsx`.

**5.** "Try again" unmounts itself without moving focus, dropping focus to `<body>`; the in-repo pattern is `ArchitectEntry.tsx:190-191`, which focuses the heading before retrying.

**6.** The Generated building option is never described — `placement.detail`, the footprint dimensions and `candidateNotes` are parsed then never rendered, so the analyst adopts a shape sight-unseen.

**7.** The option's honesty paragraph renders unconditionally, describing "this checked option" even in the state where none exists, above a card explaining its absence in engine jargon.

**8.** With the route unmounted, today's reachable state is a `role="alert"` failure card headed "unavailable right now" — assertive and transient-sounding for a permanent condition.

**9.** None of the new classes (`max-envelope-*`, `envelope-dimension*`, `generated-building-option`) exist in either stylesheet, so "visibly incomplete" is carried by sentence text alone in an unstyled default list.

**10.** Production labels and units reach the analyst as raw tokens — "maximum lot coverage ratio — 0.55 ratio", no sentence casing, no thousands separators — and every fixture models a dimension set the engine does not declare.

**11.** Out-competed rule ids and the binding-row `detail` are parsed but only the count renders, so provenance is thinner than the available data.

**12.** The nav link still reads "Proposal editor" though that view now leads with the limits panel; `navigation.ts` was outside this packet's allowed paths.

Closing: PASS — 0 blocking, 12 advisory; findings 1, 2, 3, 6 and 7 should close before the mount seam turns this surface on.
