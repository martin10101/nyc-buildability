## Findings

1. **(advisory)** ZoLa link opens in a new tab (`target=_blank`) but the link text "View this lot on the city's ZoLa map" (`AddressConfirmCard.tsx:131`) does not signal the new-tab/external-window behavior to sighted or screen-reader users (WCAG G201 best practice). Consider appending an explicit "(opens in a new tab)" or a visually-hidden cue.

2. **(advisory)** The prominent "canonical address" mixes the echoed, user-typed house number (`view.inputEcho.houseNumber`) with the canonical street/borough/zip (`AddressConfirmCard.tsx:50-57`); the view model maps no canonical house number. Honest for recognition (BBL is the authoritative identifier), but if the connector emits a canonical/normalized house number it would be more faithful to the "canonical address" label to use it.

3. **(advisory)** Placeholder copy says "Open the city's ZoLa map for the authoritative outline" (`:143-144`); spec §6 wording is "…ZoLa map **above**…". The ZoLa link does sit above the placeholder in DOM, so the directional word would improve wayfinding. Purely cosmetic.

4. **(advisory)** The producer report (`M5-T016-producer-report.md:16`) states the Confirm pack is "10 tests"; the module and CI both have/ran 11. Report-count inaccuracy only; no code impact.

None of the findings block the journey or require correction before acceptance.
