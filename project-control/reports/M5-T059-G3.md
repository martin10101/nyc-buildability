## 6. Defects

### C1 — BLOCKING: `revoke` is not bound to the property in its own URL path (High)

`services/api/app/api/v1/site_definition.py:496-533`. The `{bbl}` path parameter is shape-validated at `:506` and then **never used** — no resolver call, no condo comparison — and `store.revoke(record_id, …)` at `:519` looks the record up globally (`store.py:214-232`). The sibling `supersede` **is** bound, via the store's condo_key check (`store.py:195-199`). Reproduced on the frozen content in `wt-m5t059/services/api` with a per-BBL resolver double:

```
create for condo 103344 via 1003037502            -> 201
SUPERSEDE via unrelated property 4001237502       -> 404 confirmation_not_found   (bound: refused)
REVOKE   via unrelated property 4001237502        -> 200 revoked   condo_key of revoked record: 103344
```

A mis-addressed or hostile call terminates a **different property's** active site definition, against G0 ruling 6 ("keyed on `condo_key`; billing/entered BBLs as attributes") and the route's own resource contract. Not a D-078-R002 breach (the act is human-initiated and the transition is recorded with actor + reason), and unreachable today (router unmounted, flag-gated, uuid4 ids) — but it becomes a live IDOR the moment the slice-2 mount lands, which is exactly what the unmounted posture is meant to buy time for.

Required: bind revoke the way supersede is bound — re-read the resolver for `{bbl}` and compare `resolution.condo_key` against the stored record's `condo_key` (or add `condo_key` to `SiteDefinitionStore.revoke` + the in-memory impl, and state the binding in the ABC docstring at `store.py:76-81`) — plus a regression test asserting a cross-property revoke is a typed refusal.

### Advisory findings (non-blocking; route to DB backlog or the slice-2 packet)

- **F-2 (Low) — misnamed refusal on a malformed parcel set.** `normalize_parcels` raises `InvalidConfirmerError` for array/entry shape problems (`records.py:364-381`), so a bad `parcels` body returns client-facing `reject_code: "invalid_confirmer"` (`site_definition.py:217-229`) — a wrong cause label on a typed refusal. Suggest a distinct parcel-shape error class.
- **F-3 (Low) — comment asserts ordering the code does not have.** `store.py:174-176` claims a same-instant tie falls back to "the reverse of insertion order"; Python's sort is stable, so `reverse=True` **preserves** insertion order for ties. Reproduced: a same-`confirmed_at` supersede lists the OLD superseded record first, contradicting "newest first" (`store.py:63-65`). Unreachable from the route (`datetime.now(UTC)` microseconds) and `build_site_definition_block` selects the active view by filter not position (`records.py:514-516`), so no live impact. Fix = an insertion-sequence tiebreaker, or correct the comment.
- **F-4 (Low) — write/read key-fallback asymmetry.** The write routes fall back to `condo_key = resolution.condo_key or canonical` (`site_definition.py:375`, `:467`) while the read document emits the block only when `resolution.condo_key is not None` (`condo_records.py:669`). A multi-lot resolution with a null condo key would accept a confirmation that can never surface. No test covers `condo_key=None` (the `_multi_lot` helper has the parameter, unused at `test_site_definition_api.py:62-65`).
- **F-5 (Low) — unenforced state matrix.** `SITE_DEFINITION_STATUS_STATE_MATRIX` (`site_definition.py:106-117`) is documented as "the single source of truth for every emission path" but no test asserts any emitted `(status, state)` pair against it — unlike the precedent it mirrors (`test_condo_records_api.py:561-564`). Currently decorative.
- **F-6 (Low, display) — raw fractional-second timestamp inside a section that has a decimal gate.** `PropertyOverview.tsx:~217-222` claims "no decimal figures — this renders INSIDE the records section the D-073-R006 grep gate covers", but the confirmed branch renders `confirmation.confirmedAt` verbatim and the API always emits fractional seconds (`2026-09-20T08:23:30.089123+00:00`). That string matches the section-wide gate `expect(section.textContent).not.toMatch(/\d+\.\d+/)` at `condo-resolution-display.test.tsx:407`; the suite stays green only because that assertion's fixture carries no `site_definition` block. Format the timestamp for display, or extend/annotate the gate, before the confirmed branch is routinely reachable. (Flagging for the human-journey reviewer as well.)
- **F-7 (Info) — a unit-class entry can never be confirmed.** `_resolve_multi_lot` uses `resolve_condo_billing`, which pass-throughs any non-billing lot class (`condo_base_lot.py:175-181`), while the read document reaches multi-lot via the UNIT path too (`condo_records.py:640-650`). A user entering a unit BBL sees "not confirmed" with no write path from that entry (the shared `condo_key` still surfaces a confirmation made from the billing lot). Slice-2 (the confirm button) should close this; recording it so it is not discovered at mount time.
- **F-8 (Info) — no duplicate-record-id guard in the store.** `store.py:157` and `:200` assign `self._records[record_id]` unconditionally; a hand-built record reusing an id would silently overwrite an immutable original. Unreachable from the route (`record_id` is never read from the body; `records.py:482` always mints uuid4), but the ABC is a public interface.
