A2 — strip name doubled + no heading. The region name comes from BOTH aria-label="Active issues" and a visible <p> "Active issues" (OverviewExceptionStrip.tsx:44 and :47), so a screen reader announces "Active issues" twice (region label, then the paragraph). The title is a <p>, not a heading, so the most safety-critical block is absent from the heading outline that already includes "Site context" and "Development limits" (both h2). Consider a real heading + aria-labelledby: de-duplicates the name AND makes the strip heading-navigable (the strip is the content a hurried analyst most needs to find).

A3 — map-before-limits reading/stacking order. The column swap (deviation D1) makes the map the FIRST DOM child and the limit matrix the SECOND (PropertyOverview.tsx:371-391); on phone (≤950px single column) they stack map-above-limits. So keyboard/screen-reader/mobile users now reach the analytically important numbers AFTER the largely-visual site map (before this slice the matrix came first). Spec-faithful (§5.3 / frame O-D, producer OQ-2) and consistent with "more visually explanatory," but the owner will literally SEE the numbers below/after the map on a phone and to the right on desktop — worth an explicit owner confirm that map-first is the intended priority (one CSS line + DOM swap reverses it if not).

A4 — stale row has no actionable link. Conflict and missing rows each carry a "Review … →" link to the issues view; the stale row says "…Captured dates and retrieval status are available in Evidence. Review the retrieval dates before relying on these figures." with NO clickable path (OverviewExceptionStrip.tsx:73-80). Matches today's PropertyIssuesSummary (producer OQ-3, not a regression), but the two linked rows set an expectation the stale row doesn't meet — a "Retrieval status in Evidence →" link would close it.
