SUMMARY: FAIL — two blocking items, same root cause. The combiner's structure is mostly sound: the combined verdict and the finding union are computed in code (the model can never directly set the verdict), missing/malformed/timed-out/raised reviews are non-refutable and hold the verdict at UNVERIFIED, the model is invoked read-only through claude_reviewer.build_argv with no argv injection, untrusted model output is parsed safely and malformed/empty never applies a refutation, the child env carries no ambient credentials, all fail-closed refusals happen before any process launches, and nothing in the loop imports or calls the module (default-OFF, unwired). BUT the one security-critical path — dropping a reviewer's blocking finding via a model-proposed refutation — is defeatable: the "evidence present" check verifies only that a cited token EXISTS somewhere in the deterministic inputs, never that it is RELEVANT to the finding being dropped, and the frozen head SHA is universally present, so a prompt-injected or merely wrong combining model can drop ANY refutable blocking finding and force the verdict to PASS. The module's own docstring claim ("the model can never drop a finding by assertion") is not met. Because the combiner's entire purpose is to not let real security findings be dropped improperly, this must be hardened before it is merged-as-relied-upon / ever wired or enabled.

SCOPE / WIRING: grep confirms NO non-test module imports review_combiner / ReviewCombiner / review_combiner_enabled — not wired into the loop (point 6 PASS). 43 combiner tests pass; CI supervisor-bridge (windows-latest) PASS.

FINDINGS BY FOCUS POINT

(1) CAN THE COMBINER WEAKEN A REVIEW? — the blocking problem.
- GOOD (verified): the verdict is `_worst_unrefuted_verdict(findings)`, pure code; the model output is parsed ONLY for a `refutations` list — no code path reads a verdict/decision from the model, so the model cannot directly set the verdict. The finding union (`_collect_findings`) is pure code: one `blocking` finding per reviewer blocking_findings entry, a synthetic `verdict` finding for a bare non-approve review, and a non-refutable `unverified` finding for a missing/untrustworthy review. Probed: a missing codex review -> UNVERIFIED and its refutation is rejected (unverified findings are refutable=False); a malformed model output -> no refutation, verdict stays FAIL; both reviews missing -> model never called (0 runner calls), UNVERIFIED. Those safety properties hold.
- BLOCKING B1 (sha evidence is a universal finding-drop primitive). `CombinerInputs.has_sha` returns True when `frozen_head.startswith(sha)`, and `evidence_present` accepts a `{"type":"sha","sha":<hex>}` refutation whenever has_sha is True. The frozen head is a 40-char SHA present for EVERY unit, so a refutation citing the frozen head (or any >=7-char prefix) passes the evidence check for ANY refutable finding and logically refutes nothing. Reviewer `blocking` findings are refutable=True, so this drops real blocking findings. PROVEN by probe: a HALT_UNSAFE review with a blocking SQLi finding, refuted by `{"type":"sha","sha":"aaaa...(the frozen head)"}` -> refutation ACCEPTED, surviving findings empty, combined verdict = PASS. The producer's own tests ENSHRINE this (test lines 194 and 248 assert `{"type":"sha","sha":"aaaaaaa"}` — a prefix of the frozen head — is valid present evidence), so it is intentional, not an oversight the tests catch. EXACT FIX: do not treat the frozen head (or any prefix of it) as refuting evidence — remove the `head.startswith(sha)` branch from has_sha (and update the test asserting "aaaaaaa" is present); a sha refutation must cite a sha that is NOT the frozen head and is bound to the finding. Better: disallow sha-type refutation of reviewer `blocking` findings entirely.
- BLOCKING B2 (evidence-present checks presence, not relevance to the finding). For `file_line`, evidence_present returns True when the cited (file, line) is anywhere in the diff's new-side lines — not that it is the finding's own location; for `command_output`, True when the cited text is a substring of ANY collected command output — not that it relates to the finding. Since the producer-controlled diff has many added lines and command outputs contain abundant common substrings, the model can attach a present-but-irrelevant citation to drop any refutable finding. PROVEN by probes: a blocking SQLi finding at a.py:999 refuted by `{"type":"file_line","file":"a.py","line":1}` (line 1 is in the diff, unrelated to the finding) -> ACCEPTED, verdict PASS; and by `{"type":"command_output","text":"tests passed"}` (a present substring, unrelated) -> ACCEPTED, verdict PASS. The producer's test line 183 ("test_command_output_substring_refutes", citing "all tests passed") encodes this as intended. This is exactly the prompt-injection vector the task raised: injected text in the producer-controlled diff or a reviewer's finding text can persuade the combining model to emit refutations, and code accepts them because the cited token merely exists. EXACT FIX (any of): (a) make model refutations ADVISORY ONLY — annotate a finding as "model-disputed" but NEVER remove it from surviving_findings or change the verdict (fully preserves the stated "monotone, never weaken" invariant); or (b) allow refutation to drop ONLY the synthetic `verdict` findings, never a reviewer's explicit `blocking` finding; or (c) require the cited evidence to be structurally bound to the finding (file_line must equal the finding's own reported location; command_output must be a nontrivial token taken from the finding's detail). Also update the docstring claim ("the model can never drop a finding by assertion") to match the hardened behavior. B1 and B2 share one root cause (presence != relevance); B1 is the extreme, tautological case.

(2) READ-ONLY MODEL INVOCATION / NO ARGV INJECTION — PASS. `_propose_refutations` builds argv via `build_reviewer_argv` = claude_reviewer.build_argv(self.executable, model=self.config.model), which (verified in M0-T168) emits only [-p, --output-format json, --permission-mode plan, --model <model>], refuses every write-enabling/other permission mode and the forbidden session/resume flags, and runs assert_argv_safe which hard-denies the bypass flags (--dangerously-skip-permissions/--yolo/etc., incl. =form) and NUL/non-string. The model is self.config.model (owner-required setting), a single argv token (list exec, no shell), so a bypass-flag model -> HardDenyError and any other model cannot split into extra flags. No review field or packet content reaches argv (reviews/findings/diff travel only on stdin). Read-only via --permission-mode plan; no write ability.
(3) UNTRUSTED OUTPUT PARSED SAFELY — PASS. `_parse_refutation_proposals` + `_balanced_json_objects` is the same bounded, string-aware brace scanner as the Claude reviewer; empty/garbage -> None -> "no parseable refutations; none applied" (probed). A non-object proposal, an unknown finding_id, a non-refutable target, or absent evidence are each rejected with the finding left in place. Malformed/empty output never applies a refutation and never yields PASS by itself.
(4) ENVIRONMENT / SECRETS — PASS. env=claude_child_env() (same as claude_reviewer): minimal_env allowlist drops all ambient credentials (no ANTHROPIC_API_KEY) and forces DISABLE_AUTOUPDATER=1; auth resolves via the CLI's own HOME credential store.
(5) REFUSALS BEFORE ANY PROCESS — PASS. combine() runs, in order and before the only launch site (_propose_refutations): model-unset -> combiner_model_unset; switch-off -> combiner_disabled; _assert_independent (combiner == producer / codex reviewer / claude reviewer -> combiner_not_independent); _assert_same_frozen_head (frozen_head must be 40-hex; reviews' verified_repo_head must not be distinct from each other or from the frozen head -> reviews_of_different_heads). Probed: model-unset, switch-off, identity collision, and different-heads each refuse with runner calls = 0. The model is also not invoked when no finding is refutable.
(6) NOTHING IN THE LOOP CALLS IT — PASS (grep NONE; default-off config; ReviewCombinerConfig.enabled default False; from_mapping/review_combiner_enabled honour only a real bool True and reject unknown keys; model has NO default and an unset model refuses — D-091-R008 satisfied).

BLOCKING ITEMS
B1. The sha evidence type treats the universally-present frozen head as valid refuting evidence, making it an unconditional drop primitive for any refutable finding. Fix: stop accepting the frozen head (or a prefix) as refuting evidence; a sha refutation must cite a non-head sha bound to the finding, or disallow sha-type refutation of blocking findings. (Update the tests at lines 194/248 that assert the head prefix is present.)
B2. evidence_present checks only that a cited token exists in the inputs, not that it is relevant to the finding being refuted, so a prompt-injected/adversarial/wrong combining model can drop a real reviewer blocking finding with any present citation and force PASS. Fix: make model refutations advisory-only (never remove a reviewer blocking finding or change the verdict), or restrict droppable findings to the synthetic `verdict` kind, or require the evidence to be structurally bound to the finding; and correct the docstring claim. (Update test line 183.)

NON-BLOCKING NOTES
N1. _assert_independent is a soft guard: it is skipped when combiner_identity is empty (same pattern as claude_reviewer). The real independence is the fresh process; callers should supply combiner_identity so the collision guard is effective.
N2. The combiner does not enforce a model allowlist on self.config.model (claude_reviewer.build_argv has no allowlist param, and the combiner does not use ClaudeReviewer._resolve_model). Not an escalation (model is a single argv token; a bypass-flag model is hard-denied), and the model is an owner-required setting — but the combiner trusts the owner to set it correctly.
N3. The existing test suite encodes the presence-only semantics as intended (sha-prefix-of-head and arbitrary-substring "refute"), so current CI green does not catch B1/B2; the hardening must come with updated red/green tests proving a real blocking finding cannot be dropped by a present-but-irrelevant or head-sha citation.
N4. Credit where due: verdict-in-code, union-in-code, non-refutable missing/malformed reviews, read-only argv, fail-closed pre-launch refusals, safe output parsing, env parity, and default-off/unwired are all correct and are the right foundation; the defect is localized to the refutation evidence check.
