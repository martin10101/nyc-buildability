## Findings

No blocking (F) items.

**A1 (advisory) — late-insert layout shift (CLS) in the corner-lot case.** The record line renders only after the async record-address fetch settles, and it inserts between the entered-input note and the warnings/BBL/ZoLa/map/Continue block (`:198-204`). When it appears it nudges that block — including the "Continue with this lot" button — down by one line. It is additive (appears once), no interactive target changes label or moves horizontally, and the core identity + primary action are present from first paint, so this is a minor progressive-enhancement shift, not a block. It occurs only in the minority case the feature targets (record ≠ matched); the common equal/absent cases never insert a line. Consider reserving space or accepting as-is.

**A2 (advisory) — `aria-label` on `<strong>` is name-prohibited (A3a a11y mechanism).** Per ARIA 1.2, `strong` is in the set of roles for which accessible naming is prohibited, so a conformant screen reader is expected to ignore the `aria-label` on `<strong title aria-label>` (`:188-189`). The consequence: the raw-with-whitespace value reaches sighted mouse users via `title` (hover) but is not reliably exposed to SR/keyboard users. This is not a functional gap — the visible trimmed text is what SRs announce, and the trimmed value is the honest, useful reading (surrounding whitespace carries no meaning to an SR user). AS-4's letter is fully met (both attributes present in the DOM; S9 asserts both). If SR exposure of the exact raw value is ever wanted, wrap the value in a `<span title aria-label>` (span/generic also name-prohibited — use a visually-hidden sibling text node instead) rather than `<strong>`. Non-blocking.

**A3 (advisory) — no-normalized-street edge, residual of A2.** When the city resolves the lot but returns no printable normalized street, `confirm-address` does not render (a fallback note shows instead, `:174-179`), yet the entered-input note still reads "We show it alongside the city-matched address so you can compare them" (`:192-194`) — referencing a matched line that is absent in that rare case. This is a large improvement over the old directional "above" (which pointed at the wrong element); the new copy makes no layout claim, but the phrase "the city-matched address" is still slightly off when no such line is shown. Rare path; non-blocking.

**A4 (advisory) — three-address legibility for a first-timer.** In the corner case the analyst sees entered `1279 37th street`, matched `1279 37 STREET`, and record `3622 13 AVENUE`. The copy honestly states the record "can differ from the matched frontage" and that the BBL is the carried identity, but it never explains WHY they differ (a corner lot has two frontages on one tax lot). A skeptical first-timer may momentarily distrust the match on seeing a wholly different street before reading that the BBL is the identity. Honest and correct as written; a brief "corner lots can have more than one street frontage" note would be warmer. Non-blocking.
