INDEPENDENT VERIFICATION
1. posix_acl boundary — adversarial probe (injected lstat, on this non-root Linux host) gave the correct verdict for every case:
   - non-root-owned 0444 file -> NOT_PROTECTED (owner can chmod and re-grant write; correct analogue of Windows WRITE_DAC).
   - root 0444 file in root 0755 dir -> PROTECTED.
   - group-writable 0464 / world-writable 0446 -> NOT_PROTECTED.
   - symlink (even root-owned, injected S_IFLNK AND a real on-disk symlink via default os.lstat) -> NOT_PROTECTED with a "symlink" reason.
   - non-POSIX platform / missing file (FileNotFoundError) / unreadable (PermissionError) -> UNKNOWN, never read as protected.
   - parent group-writable OR parent non-root-owned -> overall NOT_PROTECTED (parent is independently evaluated with the SAME clauses, closing the rename/replace vector).
   Uses os.lstat as default (does NOT follow the final symlink) — the correct choice; os.stat would have let a root-owned symlink-to-root-target read PROTECTED. The combine rule requires BOTH file and parent PROTECTED, and NOT_PROTECTED dominates UNKNOWN. Verdict dataclasses are literally os_acl.AclVerdict / os_acl.ControllerConfigAclVerdict (same shape on both platforms; confirmed identity `is`). TOCTOU between check and read is not exploitable by a non-root user: a genuine PROTECTED verdict already proves the parent dir is root-owned and non-writable, so no unprivileged swap is possible, and os_acl's design retains config.py digest/identity verification regardless.
