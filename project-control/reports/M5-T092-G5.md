M5-T091 - PDF site-plan writer hardening (DB-053 a-d)
- [SOUND] Single escaper + screen: all four caller-text fields (address, bbl, generated_at, generator_version) are screened in _screen_caller_text (pdf_sheet_writer.py:224) BEFORE anything is drawn, and reach the stream only via _draw_text -> _escape_pdf_text (:417, :424). No other caller-string path exists; dimension/scale/title text is server-computed or hardcoded (still escaped).
- [SOUND] No literal-string breakout: _escape_pdf_text ASCII-sanitises first (CR/LF/non-ASCII -> "?", :442) then backslash-escapes ( ) \ (:435); latin-1 encode at :342 is safe because everything is ASCII post-sanitise. Probed unbalanced parens, lone backslash, CR/LF, non-ASCII, ")(", "((", "\\(" - all contained inside the literal string; the repo strict reader round-trips them.
- [SOUND] Finite guard: _num raises _RenderRefused -> non_finite_value (:453), caught at :211; nan/inf can never become a token. No partial output - render returns either a SitePlanRefusal or the complete bytes from _assemble_pdf.
- [SOUND] Numeric-type refusals: _coerce_vertex (:291-315) rejects bool, non-Real, numeric strings, Decimal, complex; int-beyond-float -> OverflowError -> oversize_input. Claim screen robust: separator-collapse _claim_key + printed-form screening refuses AS_OF_RIGHT / "maximum  allowed" / As.Of.Right (probed).
- [ADVISORY, LOW, NON-BLOCKING - producer's D2] No length bound on caller text. Probe: a 200,000-char address renders a 201,603-byte PDF; output is linear in caller text. This is NOT a breakout (bytes stay escaped) - it is a latent unbounded-output DoS, unreachable today (unwired). RULING for the pre-wiring stage: does not block this hardening increment, but MUST be closed at the wiring packet - add a per-field max length with a typed refusal (mirror the 1024-vertex / +-1e8-coord caps) before any route/user text reaches it. Recommend recording it as a precondition on the wiring task.
