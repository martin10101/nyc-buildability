## 1. Fail-closed properties (the security core)

**1a. Every rule status `needs_review`; nothing can produce a Verified result — PASS.**
- Probe (registry load + evaluate one district per rule, `as_of=None`, no G6): all five family rules report `status=needs_review`, `release.independent_review=pending`, `release.qualified_human_approval=pending`; every evaluation returned `coverage=conditional` with `verified_eligible=False`. Observed FARs: r1-r2-r3 R1-1→0.75, r2x-r4 R4→1.0, r5 R5→1.5, r6-r12 R10→10.0, wide-street R8→6.02.
- Code: `lifecycle.assert_agent_authorable` (called in `build_rule_definition`) rejects any status beyond `needs_review` at load; `evaluator.evaluate` sets `verified_eligible = status==published AND _approval_matches(...)`, so a draft rule's `base_coverage` is `conditional` and `coverage.most_severe` can only move away from `verified`, never toward it. Two independent barriers (load-time status guard + evaluate-time gate).

**1b. Wide-street conditional NEVER returns the higher value (AS-3, the worst possible output) — PASS.**
- Probe (exhaustive over the 4 conditional districts × 4 housing_program values incl. absent): returned `max_residential_far` was always the conservative value (R6 2.20, R7-1/R7-2 3.44, R8 6.02); the higher set {3.00, 4.00, 7.20} never appeared as an output; `wide_street_far_alternative` was surfaced as an applied `conditional_alternative` in every case; coverage always `conditional`.
- Code: the computation step selects only `standard_far_by_district` (the conservative map) via `param_select`; `wide_street_far_by_district` is a provenance-only parameter never referenced by any computation step or determination. The `wide_street_far_alternative` exception has `condition: null` (always surfaced) with `effect: conditional_alternative`, so it downgrades coverage and records a note but cannot emit a value. Structurally the higher value has no path to `outputs`.

**1c. Drifted source REFUSES at load — PASS.**
