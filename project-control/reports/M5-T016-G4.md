The confirm-test S5 (`address-confirm.test.tsx:302-330`) asserts source_id, host, digest, connector-correlation-id, request-params, and source-facts, but never the retrieved-at value nor the disclosure GRC codes. (The S1 warnings test at `:198` asserts `warning-grc-message` — a *different* element/testid in the warnings block, not the disclosure GRC line, which has no testid.) A mutant that drops the retrieved-at clause or the disclosure GRC line **survives the whole suite** — and the producer's own named-mutant table (report §4) omits both, confirming the gap. The fields render correctly, so this is a test-completeness defect, not a functional one. **Correction:** add assertions in the S5 test that the disclosure contains the fixture `retrieved_at` value and both GRC codes.

**F2 — advisory.** "confidence 1.0 never a coverage/verified badge" is enforced structurally (address-api deliberately omits `confidence` from `SourceFactView`) and covered in spirit by the `\bVerified\b` absence check (`:338`), but there is no explicit assertion that the value `1.0` / a coverage number is absent from the source-facts row. Consider adding `expect(screen.getByTestId("source-facts").textContent).not.toContain("1")`-style guard against a future re-mapping of confidence.

**F3 — advisory.** S1 "canonical address LARGE (section-title scale)" — the card applies `className="section-title"` + `fontSize:1.5rem` (`AddressConfirmCard.tsx:66-67`) but no test asserts the scale/class; visual prominence is a G3/human-journey concern, hard to pin in jsdom. Noted, not blocking.

**F4 — advisory (report hygiene).** Producer report §1 table says the confirm pack has "10 tests"; the actual pack and CI both report **11** (report §4 also lists 11). Harmless miscount; worth correcting in the report.

**F5 — advisory.** `address-confirm.test.tsx` duplicates the harness (`resolvedDoc`, `jsonResponse`, `stubFetchOnce`, `fillAndSubmit`) from `address-resolution.test.tsx` rather than sharing a support module. If the render line is dropped, `body` loses `"retrieved 2026-09-12T0000000000"` and the assertion fails. Fixture-bound (derived from `doc.provenance.retrieved_at`, not retyped). Killed.

**Mutant 2 — dropped in-disclosure GRC line: KILLED.** New assertion `expect(body).toContain(`Geosupport return codes: ${doc.grc} / ${doc.grc2}`)` → `"Geosupport return codes: 00 / 00"`, which matches the card's disclosure line (AddressConfirmCard.tsx:159-162, textContent `"Geosupport return codes: 00 / 00"`). Crucially `body = details.textContent` is scoped to the provenance `<details>` element, and S5 test 1 uses the plain `resolved` fixture (no warnings block rendered), so this genuinely targets the in-disclosure line, distinct from the warnings block's `warning-grc-message`.
