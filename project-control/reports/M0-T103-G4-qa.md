## Findings

**ADV-1 (non-blocking — test-hygiene regression introduced by M0-T103).**
In `tools/test_agent_supervisor_capability_probe.py`, the `@pytest.mark.skipif(shutil.which("claude") is None, ...)` decorator that previously guarded `test_live_reprobe_claude_version_matches_fixture` now sits directly above the newly-inserted `post()` fixture (the git diff shows the fixture was inserted between the decorator and the test). Marks applied to fixtures have no effect — pytest emits `PytestRemovedIn9Warning: Marks applied to fixtures have no effect` (line 166). Consequences:
- The `post()` fixture is not actually skippable (mark is a no-op); and
- `test_live_reprobe_claude_version_matches_fixture` has **lost its skip-guard**. On a runner without `claude` installed, `cp._run(["claude","--version"])` returns `status:"absent"`, so `assert rec["status"]=="supported"` would make the test **FAIL instead of skip cleanly** — violating the module's stated "Live CLI re-probes are feature-detected and cleanly skipped when the executable is absent (D-024 16.1)" contract (section header at line 164 literally reads "skips cleanly when absent"). The sibling codex test (line 202) still carries its skipif correctly.

**Why non-blocking:** the direction is fail-safe (loud failure, never a false green), it does not affect any delivered evidence, all 18 tests pass on the target machine and CI (where claude/codex are present), and the mutation teeth are proven RED-capable. Recommended follow-up correction: move the `skipif` back onto `test_live_reprobe_claude_version_matches_fixture` (or add a separate `skipif` to the test) so the absent-CLI path skips rather than fails.
