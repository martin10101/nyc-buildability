## 3. Threat-by-threat findings

### T1 — SSRF / URL injection: PASS (1 LOW advisory)
Traced route param → `normalize_bbl` → `build_outline_query_url`. The BBL is strictly validated (`^[1-5][0-9]{5}[0-9]{4}$`), a canonical-form guard rejects any non-canonical value (`DisallowedRequestError`), and the where clause uses `int(normalized.canonical)` interpolation — **no attacker-controlled substring can reach the URL**. Host/path/fields/paging are all constants imported from the immutable connector (`SERVICE_ROOT`, `LAYER_NAME`, `OUT_FIELDS`, `MAX_FEATURES_PER_LOT`); only `&f=geojson&outSR=4326` is appended. The fetch seam receives the canonical BBL, never request data. Injection attempts (`" OR 1=1"`, `"&f=json"`, `"'; DROP"`, newline, short BBL) are all refused by `test_url_builder_refuses_non_canonical_bbl`.
- **LOW-1 (defense-in-depth):** `default_fetch` uses `urllib.request.urlopen` with the default opener, which follows 3xx redirects without re-pinning scheme/host. Not attacker-triggerable (the attacker controls only an integer BBL; a redirect would have to be issued by the pinned, trusted DCP ArcGIS host). Remediation: disable redirects or re-assert `https` + `services5.arcgis.com` on redirect, matching the authoritative connector's transport posture (producer already flagged the minimal-transport follow-up in report §7.4).

### T2 — Response trust (external untrusted data → client): PASS (1 LOW advisory)
Parsing is fail-closed at every step: non-200 → `upstream_error`; non-JSON → `malformed_response` (ValueError caught); non-object / non-`FeatureCollection` → malformed (ArcGIS 200-with-error-object detected separately); present-but-wrong CRS → `wrong_crs`; `features` not a list → malformed; returned-BBL mismatch → `result_mismatch`. Geometry is structurally validated (`_transportable_geometry`: Polygon/MultiPolygon only, rings ≥4 positions, each position exactly 2 **finite** numbers — `math.isfinite`, bool excluded). Critically, the emitted geometry is re-validated against the **closed** contract (`additionalProperties:false`, `required:[type,coordinates]`) before send, so an attacker-injected extra geometry key would be rejected to a typed 500 rather than passed through. Response size is bounded (`_MAX_BODY_BYTES = 16 MB`, `read(N+1)` + over-limit → typed `malformed_response`). Deeply nested JSON → `RecursionError` → caught by the route's `except Exception` → typed 500 (no traceback leak).
- **LOW-2:** No explicit cap on coordinate count / ring count / polygon count beyond the 16 MB body bound; the 16 MB ceiling is generous versus the ~120 KB observed max. Bounded and fail-closed, but a tighter bound (e.g. 2 MB) would reduce client-DoS surface. Note the 16 MB bound lives only in `default_fetch` (bypassed by the offline injected seam), so it is present but not exercised by tests.

### T3 — Honesty-as-security: PASS

Condo unit (zero features) → typed `no_outline` / `condo_unit_lot_no_polygon`, `geometry=null`, never fabricated. `no_feature_for_bbl` distinguished from condo-unit via imported `_condo_classification` (verbatim semantics, not forked). Invalid geometry → typed `invalid_geometry` 200, never a 500 traceback. `display_only=true`, `crs="EPSG:4326"`, the ±20 ft `accuracy_note`, NYC DCP `attribution`, and `disclaimer` are stamped on **every** outline outcome and asserted by `test_every_outcome_carries_display_markers`.

### T4 — Route posture: PASS
Flag checked FIRST, before any correlation id or input touch; absent/empty/unknown → generic `404 {"detail":"Not Found"}` with **no** `X-Correlation-ID` and no body hint (byte-indistinguishable from an unmounted path; `_TRUE_TOKENS` fail-safe verified in `config.py`, which is untouched). `include_in_schema=False` (not in `/openapi.json`). Body-less GET; POST → 405. Malformed BBL → typed 422 with `X-Correlation-ID`, `raw_value` repr-sanitized, and **no** connector call (landmine fetcher proves no I/O). `X-Correlation-ID` on every non-404 response. No new auth surface; `main.py` is an additive `include_router` only; **no CORS/config change** (`config.py`, `main.py` CORS block unchanged).

### T5 — Renderer parity (M5-T012 lesson): PASS (2 LOW advisories)
The route applies **both** renderings before send — `json.dumps(allow_nan=False)` and `json.dumps(ensure_ascii=False, allow_nan=False).encode("utf-8")` (`_assert_json_safe`) — failing closed to a typed 500 on NaN/Infinity or unpaired surrogate. Tests assert both forms on every 200 body. The only verbatim service-supplied strings that enter the success envelope are `source.dataset_version` (feature `Version`) and `lot_identity.borough`; a surrogate in either fails closed via `_assert_json_safe` → typed 500.
- **LOW-3:** The connector's own `validate_lot_geometry_document` performs only the `allow_nan=False` (ensure_ascii=True) check, which does **not** raise on lone surrogates. The surrogate defense therefore lives solely at the route boundary; a non-route consumer of the public `build_lot_outline` would not get it. Recommend adding the `ensure_ascii=False).encode("utf-8")` check to `validate_lot_geometry_document` and a test with a surrogate-bearing `Version`/`Borough`.
- **LOW-4:** On the **error** path, `UnexpectedCRSError.detail["crs_name"] = str(name)[:64]` copies an untrusted upstream string via `str()` (not `repr()`), and the 502 JSONResponse is emitted **without** a renderer-parity guard. A lone-surrogate CRS name would raise `UnicodeEncodeError` inside Starlette's render → untyped ASGI 500 instead of the intended typed 502. Not attacker-triggerable (requires the trusted upstream to return a surrogate CRS name); consequence is a typed→untyped error downgrade, not data exposure. Remediation: `repr()`-sanitize `crs_name` (as `returned_bbl` already is) or apply the encode-check to error bodies. `dataset_version`/`borough` also lack a `maxLength` in the closed contract (`non_empty_string` has no upper bound); bounded in practice by the 16 MB body and proper JSON escaping, so LOW.
