3. FAIL-CLOSED COVERAGE — complete for admission.
Every typed error path (slot_lock_timeout, slot_lock_error, slot_state_unreadable, slot_state_write_failed) raises SlotError; try_reserve wraps the whole locked body in `except SlotError -> _fail_closed()` returning admitted=False, reservation=None (:421-422). admitted=True is produced ONLY by the explicit success line after lock-held + count read + admit verdict True + _write succeeded (:415-420). Any UNEXPECTED escaping exception (e.g. RecursionError/MemoryError, N3) propagates out of try_reserve, so the caller's `grant = try_reserve(...)` raises and the reserve() context body never runs -> no spawn. There is no path where a caller receives a grant it would treat as admitted after an error. release() fail-closes to "leave the reservation in place" on any lock/state error (:442-443) — never falsely frees a slot. Verified by test_corrupt_state_file_fails_closed, test_lock_error_fails_closed.
Race correctness: count+decide+reserve all under the exclusive lock, written before release, so two lanes cannot both read the pre-reservation count — proven by test_global_last_slot_never_double_taken (6 real procs -> exactly 2) and test_per_lane_last_slot_never_double_taken (-> exactly 1). Takeover is race-safe (fresh lock_id per attempt + re-read confirm; last os.replace wins, loser re-reads mismatch and waits).

4. DENIAL OF SERVICE — fail-closed trade-off, disclosed.
- A live holder is NEVER deemed stale (stale = dead/reused pid only, liveness-based not time-based), so there is no lock-expiry/fencing hazard: while alive we keep the lock until release/death. A crashed lock-holder or crashed reservation-owner IS reclaimed on Linux (determined-negative via /proc) — test_dead_process_reservation_is_reclaimed, test_reused_pid_reservation_is_reclaimed, test_invalid_pid_reservation_is_reclaimed.
- A holder whose liveness is UNDETERMINED, or a live-but-hung holder, blocks all reservations until it dies/times out (acquire -> slot_lock_timeout -> no slot). This is intended and DISCLOSED (docstring ~:28-38, :73-74 "a stuck holder fails closed"; mirrors locking.py's "refusing to run is safer than two supervisors"). On Linux the undetermined window is narrow and the critical section is microseconds, so this requires a kernel-level IO hang. Correct direction (never over-admit). See N4 for the monitoring recommendation.
- No unbounded state growth: dead entries pruned on every read and rewritten on admit/active/release.

NON-BLOCKING NOTES

Gated by runtime-dir perms (not world-writable under default umask) and the same-user trust boundary; identical to locking.py:287-289. Defense-in-depth: create temps with O_EXCL (os.open O_CREAT|O_EXCL) or tempfile.mkstemp in the same dir.
N2 (INFO): Dir/files created with default umask (0755/0644 — world-readable). Contents are non-secret, so no credential exposure; tightening to 0700/0600 (or an explicit mode on mkdir) would remove cross-user visibility of pids/tokens/lanes. N3 (INFO): JSON read has no explicit size/depth cap and catches only (OSError, ValueError); a crafted deeply-nested (RecursionError) or huge (MemoryError) state file escapes as an untyped exception rather than a SlotError. Still fails CLOSED at the caller (no spawn), but not a clean typed refusal. Requires runtime-dir write access to exploit. Consider bounding read size / broadening the except to a generic fail-closed refusal.
N4 (INFO, disclosed): Recommend operator monitoring/alerting on repeated slot_lock_timeout, since a hung/undetermined holder parks all lanes by design.
