G5 M5-T099 — Part 3/4. FINDINGS.

F1 — MEDIUM, BLOCKING (add to plan / mandatory PKT-D acceptance criterion): Content-Disposition filename injection not addressed. §2 interpolates caller-influenced <bbl> and <generated_at> (a caller-supplied string, never a clock — pdf_sheet_writer.py:114-116) straight into filename="site-plan-<bbl>-<generated_at>.dxf". The plan's only caller-text controls are a length cap + claim-word screen; neither strips CR/LF, ", ;, or non-ASCII from a response-header value. Caller text in a Content-Disposition value unescaped = header-injection / response-splitting / filename-spoof. Starlette rejects CR/LF in header values, which blunts raw response-splitting, but NOT quote/`;`-breaking of the filename, extension spoofing, or non-ASCII handling — explicit sanitization is still required (defense in depth). REMEDIATE: build the filename from a server-side allowlist token ([A-Za-z0-9._-], CR/LF/quote-stripped) with RFC 6266/5987 filename* for any non-ASCII; never raw caller text. The team-lead checklist named this; the plan omits it.

F2 — import parse-time controls under-specified. (a) BLOCKING; (b)-(e) ADVISORY. PKT-F (DXF import) and PKT-K (PDF object-stream resolver) are the highest-risk future work but get one-line rows. Name these so each packet contract carries them:
(a) BLOCKING — decompression budget for PKT-K. Widening sheet_reader to PDF 1.5+ object/xref streams adds zlib inflate → decompression-bomb exposure; no output-size/ratio cap is named. Require an absolute inflated-bytes cap + ratio guard before PKT-K is contracted.
(b) raw HTTP upload ceiling at the import route via the bounded-streaming T053 primitives BEFORE the body is materialized (the "DxfLimits clamp" fires only inside read_dxf, after buffering).
(c) off-event-loop parse + per-request wall-clock deadline (cancellable), as export §2 has and max-envelope does; the import rows have neither.
(d) content-type / magic-byte check on the upload.
(e) persistence/RLS: state explicitly that the import path persists nothing (map-to-draft in memory → no storage, no RLS surface); if persistence is ever added, private bucket + tenant RLS + size cap.
NOTE: import EXPOSURE itself is handled well (dedicated double-flag, unmounted, sequenced after reader hardening); F2 is about NAMING parse-time controls, not an open hole.
