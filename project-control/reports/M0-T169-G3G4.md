G3 (CODE QUALITY / CORRECTNESS) -- FAIL

BLOCKING G3-1: the `sha` refutation evidence is trivially satisfiable; a model can drop any refutable finding (including HALT_UNSAFE) and flip combined FAIL -> PASS by assertion.
- Mechanism: `_refutation_prompt` (review_combiner.py:595-604) HANDS the model `inputs.frozen_head`. `CombinerInputs.has_sha` (lines 135-145) returns True when the cited 7-40 hex token (a) prefixes the frozen head (`head.startswith(sha)`), or (b) appears anywhere in `diff_text + command_outputs` -- which includes git `index <sha>..<sha>` framing lines. `evidence_present` (lines 200-204) accepts any `{"type":"sha","sha":<7-40 hex>}` that `has_sha` passes. So the first 7 chars of the frozen head are ALWAYS a valid "refutation" of ANY refutable finding.
- Reproduction (ran in /root/project/rv-300 with the venv): a codex HALT_UNSAFE review (blocking finding "danger: writes outside scope") + a claude CONTINUE; the fake model returns `{"refutations":[{"finding_id":"codex:blocking:0","evidence":{"type":"sha","sha":"fffffff"}}]}` where frozen_head="f"*40. Result: codex_verdict=FAIL, claude_verdict=PASS, COMBINED VERDICT=PASS, finding refuted=True, refutations_accepted=1; the prompt provably contained the head; `evidence_present({"type":"sha","sha":"fffffff"}, inputs with empty diff/cmd)` returns True. A HALT_UNSAFE safety finding is dropped to PASS.
- The test suite ENSHRINES this: `test_short_sha_prefix_of_head_refutes` (test file 192-198) and `test_evidence_present_unit` (line 248, `"aaaaaaa"` with HEAD="a"*40) assert the head-prefix SHA refutes/is-present as CORRECT behavior, so no mutation test catches it; `test_halt_unsafe_with_fake_evidence_stays_fail` only exercises an ABSENT file_line (777), never a trivially-present SHA against HALT_UNSAFE.
- Impact: defeats the central "never weaker" guarantee for all refutable (blocking + synthetic verdict) findings, and the module docstring's explicit claim "the model can never drop a finding by assertion" (review_combiner.py:28-32) and the PR body line "Never weaker than either review. FAIL never becomes PASS" are false for this class. (Mitigations that keep it from being catastrophic, but not from being blocking: `unverified` findings are non-refutable so a reviewer that produced no trustworthy decision still holds; the combined review is advisory and the refutation evidence+rationale is preserved in to_dict() for the human gate. The computed verdict is still a load-bearing, directive-mandated output and is unsound.)
- EXACT FIX: make the `sha` kind non-trivial -- in `has_sha`/`evidence_present`, count a SHA ONLY when it is a member of `extra_shas` (a supervisor-vouched, out-of-band commit), and explicitly EXCLUDE (i) the frozen head and every prefix of it, and (ii) `sha in (diff_text + command_outputs)` substring matches (drop the `head.startswith(sha)` and haystack-substring paths). Then flip `test_short_sha_prefix_of_head_refutes` and the `"aaaaaaa"` case in `test_evidence_present_unit` to assert REJECTION, and add a mutation test proving a HALT_UNSAFE/blocking finding is NOT dropped by a head-prefix or index-line SHA. Also correct the docstring (lines 28-32) and the PR body "FAIL never becomes PASS" headline to state the true, narrowed guarantee.

Non-blocking G3 notes:
- N1 (presence vs relevance, general): `file_line` and `command_output` likewise check PRESENCE not RELEVANCE -- the model is handed the diff and the command outputs, so it can cite any present line/substring to "refute" an unrelated finding (e.g. a context line like tools/foo.py:11, or a common transcript substring). This is inherent (code cannot judge semantic relevance) and is acceptable given the advisory framing + preserved evidence, BUT the downstream gate must never treat a model-refuted FAIL as an automatic PASS -- recommend the combined review carry that caveat, and/or the computed verdict not drop below the UNION verdict on model-only refutations. The SHA case (G3-1) is the egregious, universally-trivial instance and must be fixed; file_line/command_output are weaker-but-bounded and are a design note, not a blocker.
- N2 (synthetic `verdict` finding is refutable): a bare non-approve review (REVISE/STOP_FOR_OWNER/ROTATE_SESSION with no itemized blocking finding) yields a `verdict` finding with refutable=True (lines 303-308), so the model can argue away a reviewer's considered non-approve verdict. Consider making the synthetic `verdict` finding NON-refutable (like `unverified`) -- there is no itemized claim with checkable evidence to refute. Not blocking.
- N3 (empty combiner identity skips independence): `_assert_independent` returns early when `combiner_identity` is "" (lines 524-526), silently skipping the producer/reviewer guard. Mirrors claude_reviewer's accepted pattern; consider requiring a non-empty identity when enabled. Not blocking.
