M5-T102 G5, part 2/3 — BYPASS MATRIX (probed in-memory from services/api):
- Separators (_ - . / space tab newline) and case: CAUGHT.
- Zero-width / BOM (U+200B/200C/FEFF) BETWEEN words of a multi-word claim: CAUGHT (the barred key carries spaces, so the collapsed separators match).
- Unicode homoglyphs (Cyrillic A, fullwidth letters), combining marks, and NFKC-normalizable ligatures (ff-ligature -> FF, sharp-s -> SS): claim_key does NOT normalize these, so the screen ALONE does not catch them (e.g. Cyrillic-A "APPROVED" -> key " PPROVED" -> None). BUT this is MOOT in every writer today: GLB charset-refuses them, DXF _sanitize_value refuses them, and PDF maps them to '?' AND screens the printed form — so none can render as a clean claim on any surface. (A ligature can only DEFEAT a match, never produce a clean printed claim, because it prints as '?' / is refused.)
- ReDoS / cost: contains_claim_word is linear — the regex [^A-Z0-9]+ has no catastrophic backtracking. Measured: 400k chars = 17 ms; 200k separators = 3 ms; 100k sharp-s (key expands ~2x via upper()) = 13 ms. No blowup on bounded-but-large input.
- The unbounded caller-text OUTPUT-length DoS flagged in M5-T091-G5 (LOW, deferred to the wiring packet) is UNCHANGED here — this module does not bound length and is not expected to; that precondition still rides on wiring.
- The returned `barred` value is always a fixed literal from CLAIM_CLASS_WORDS, so refusal messages that interpolate it leak no caller data through that argument.
