## Findings

**F1 — ADVISORY (Medium; MUST-FIX-BEFORE-WIRING). Shape guards are anchor-leaky and the RAW (non-canonical) input is interpolated into the URL.** `dtm_condo_soda.py:178` `_STRICT_BBL_RE = re.compile(r"^\d{10}$")` and `:181` `_CONDO_KEY_RE = re.compile(r"^\d{6}$")` use `$` (matches before a trailing `\n`) and non-ASCII `\d` (matches Unicode digits). Empirically confirmed: `STRICT.match('3022647515\n') → True`, `STRICT.match(<10 Arabic-Indic digits>) → True`, `KEY.match('123456\n') → True`. Because `classify_lot` accepts `'3022647515\n'` (normalize_bbl internally `.strip()`s it, so it does not reject) and `resolve` interpolates the **raw** `bbl` (`:598` `f"...?condo_billing_bbl={bbl}"`, also `:635,:667`; `:742` for condo_key), the newline reaches the transport. Reproduced with an injected transport: URL passed = the billing URL with a literal trailing `\n`.
*Security impact is contained, hence ADVISORY not BLOCKING:* the real `urllib_transport` blocks control chars in the URL (`http.client.InvalidURL`), so no request is sent — fail-closed. `\d`/`\n` cannot inject query-structural characters, so no parameter/path/host injection and no SSRF. No fabricated resolved result is producible. *But* the contract "fail closed on any other shape … never an exception for a well-formed input" is violated: the `\n` case fails with an **uncaught, untyped** exception (`InvalidURL`) instead of `BBLValidationError`, and a non-urllib transport would receive a malformed URL verbatim.
*Remediation:* validate with `re.compile(r"\d{10}", re.ASCII).fullmatch(...)` / `\d{6}` (confirmed `fullmatch('3022647515\n') → False`), and interpolate `normalize_bbl(bbl).canonical` (not the raw input) into the URL. Apply the same to condo_key. The orchestrator should bind this fix (with tests) as a precondition on the wiring packet that first gives this module a live consumer.

**F2 — ADVISORY (Low). `_collect_base_lots` validates `condo_base_bbl` with the same leaky `_STRICT_BBL_RE`** (`dtm_condo_soda.py:488`). A Unicode-digit or trailing-`\n` `condo_base_bbl` in a response would pass the guard and enter `base_bbls`. Source is the trusted HTTPS NYC host (and redirects are refused), so this requires source compromise/MITM; low risk. Fix rides along with F1 (`re.ASCII` + `fullmatch`).

**F3 — ADVISORY (Low). Test-adequacy gap.** The malformed-input parametrization (test file:386-398) covers leading whitespace `" 3022647515"` (correctly fails via the `^` anchor) but has NO trailing-newline, trailing-space, or Unicode-digit case — exactly the class F1 exposes. Add negative cases for `'3022647515\n'`, a Unicode-digit BBL, and a Unicode/`\n` condo_key asserting `BBLValidationError` (and no transport call) once F1 is fixed.

**F4 — ADVISORY (Info). No explicit `$limit`/record cap in the query.** DoS is already bounded by the 10 MB body cap and Socrata's default page size; an explicit `$limit` would be defense-in-depth only. Not required for this gate.
