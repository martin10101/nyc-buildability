== Response handling — SAFE, fail-closed ==
- Body size capped at 10 MB (transport.py:62 MAX_RESPONSE_BYTES, :140-148 _bounded_read) — oversize bodies raise TransportFailure, never an unbounded read.
- JSON parse guards ValueError AND RecursionError (:596-602), so deeply nested JSON becomes a typed malformed_response, not a crash. Non-object bodies, missing features array, wrong CRS, over-page, schema drift, paging pathology all raise typed internal errors (:603-714).
- The public fetch wraps the whole pipeline in try/except (:1050-1075) and converts EVERY exception — including geometry/shapely errors during _build_building — into a FootprintRefusal. fetch_context_buildings never raises (verified by test :773-780).
- The catch-all internal_error keeps ONLY type(exc).__name__ (:1066-1069, base error_type :205). This is the SAFE choice: no exception message, stack, path, or upstream body text leaks into the refusal. Documented as deviation #1. Acceptable — it favors non-disclosure over debuggability; a programming bug is still surfaced (status=refused, class name recorded).

== Advisories (all NON-BLOCKING; for the WIRING packet, not this connector) ==
A1 (LOW). Untrusted source text flows out verbatim: attributes=dict(attrs) (:943) plus string fields geom_source/last_status_type (_text_attr :835-840). This connector MUST keep them verbatim for provenance, so this is not a defect here — but the wiring/report/3D consumer must escape these on render (per .claude/rules/backend-api.md "treat source text as untrusted"). Flag for the consuming packet's review.
A2 (LOW). Response-side resource use is bounded but large in the worst case: the 10 MB/body cap holds per request, yet up to 50 pages x retained features (cap 2,000, each carrying verbatim geometry) could retain a few hundred MB under a hostile/compromised upstream. Realistic NYC responses are tiny, and SSRF to a non-official host is already prevented, so this needs the official host to misbehave (TLS-protected). Consider a per-geometry vertex cap and/or a cumulative-bytes ceiling when wiring; not needed pre-wiring.
A3 (LOW). No overall wall-clock deadline across paging: each call is bounded (timeout 30s x 3 attempts + jittered backoff), but a 50-page pathological sequence could accumulate. Wiring should thread an AnalysisBudget (already supported, transport.py:452) and/or lower max_attempts for interactive paths.
A4 (INFO). correlation_id log-forging — see part 2; prefer a server-generated id at the wiring seam.
