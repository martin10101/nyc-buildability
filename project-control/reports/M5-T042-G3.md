## FINDINGS

**1. ADVISORY — `retrieved_at` stamped before I/O and shared across queries.** `dtm_condo_soda.py:569` (and `:739`) computes `retrieved_at` before any fetch, and every provenance entry in a multi-query `resolve()` (unit + condo_key expansion) reuses that one value. The accepted sibling `pluto_soda.py:654-657` deliberately stamps `retrieved_at` **after** the successful response (its G3 D3 finding) precisely because a pre-request stamp can precede actual retrieval across retries. Provenance-precision only; deterministic and honest. Recommend aligning with the pluto post-response stamp (or a per-query timestamp) in the later wiring packet.

**2. ADVISORY — undocumented `BBLValidationError` code `"wrong_shape"`.** `dtm_condo_soda.py:333` raises `BBLValidationError("wrong_shape", …)`, but the code vocabulary enumerated in `bbl.py:44-47` is `empty/non_numeric/negative/non_integer_decimal/wrong_length/invalid_borough/invalid_block/invalid_lot/invalid_component`. `"wrong_shape"` is not in that set (functionally fine — the constructor accepts any string — but it is taxonomy drift). Prefer `wrong_length`/`non_numeric`, or extend the documented vocabulary.

**3. ADVISORY — field overloading in `resolve_by_condo_key`.** `:771-797` sets `input_bbl=<condo_key>` and `lot_class=LOT_CLASS_NOT_A_CONDO` on both resolved and unresolved results. Stuffing a 6-digit condo_key into a field named `input_bbl` and reusing `not_a_condo` as a filler lot_class overloads the result contract. Consider a dedicated `input_kind`/`condo_key` distinction (or `lot_class=None`) when the seam is wired.

**4. ADVISORY (test adequacy) — dtm-local error branches unexercised by this suite.** No dtm test drives: the 400 schema-drift vs non-drift split (`_raise_for_unexpected_status`, `:365-386`), the `_fetch_rows` JSON guards (non-list / non-dict / invalid-JSON, `:443-464`), or the terminal typed errors (`RateLimitedError`/`SourceTimeoutError`/`SourceUnavailableError`). These branches mirror proven pluto/ztldb code and the retry engine is covered centrally; the packet also defers rate-limit as live-era row C13. Not blocking, but a G4/later pass should add offline transport-stub cases for the 400-drift path and the non-list-body guard so this connector's own classification is directly proven.

**5. ADVISORY (cohesion ruling) — ACCEPTABLE WITH JUSTIFICATION.** `modularity_check.py --check` exits 0; `dtm_condo_soda.py` sits in the **warn band (≈625 SLOC, between WARN 600 and JUSTIFY 750)** — "above the warning threshold," below the justification and hard thresholds. It is a single cohesive responsibility (lot classification + billing/unit/condo_key query paths + one typed result + provenance), with no responsibility mixing, comparable to the accepted sibling SODA connectors.
