## Per-item mapping (finding -> change -> tests)

### B-1 (loop.py:983-1004) — the forwarded prompt now has a consumer
- `tools/agent_supervisor/loop.py`: `ForwardResult` gains `sent_prompt` (the exact bytes
  of the outbox row marked sent; `to_dict()` carries its digest, not the bytes — the bytes
  are already journaled in the outbox envelope). `forward_exactly_once()` sets it, and on
  the resumed-unsent crash path it reads the PREVIOUSLY journaled row's own prompt (the
  row is resumed, never re-rendered). `run()` threads `result.forward.sent_prompt` into
  the next `run_cycle` in supervised mode, and FAILS CLOSED
  (`forwarded_prompt_unavailable`) if a sent forward ever lacks its prompt bytes rather
  than silently re-sending the original. The now-unused `_outbox_state` helper was
  removed (its logic is inlined where the resumed row is fetched). Shadow is untouched:
  it forwards nothing and stops after one observation.
- Tests (`test_agent_supervisor_loop.py::ForwardedPromptThreadingTests`): the mandated
  2-cycle supervised fake run asserting the SECOND unit's received prompt is the
  forwarded one (via `FakeRunner.prompts`); byte-equality of the threaded prompt with the
  outbox envelope row; resumed-unsent rows thread their OWN journaled prompt; the run
  report carries a digest, not the prompt.

### B-2 (loop.py, state_machine.py, cli.py) — every cycle ends in a resumable state
- Design choice: a NEW `POLICY_CHECK -> PREFLIGHT` edge on trigger `cycle_closed`
  (state_machine.py), fired after a completed shadow observation and after
  DENY_AND_CONTINUE — NOT admission of POLICY_CHECK to `CYCLE_ENTRY_STATES`. Reasoning:
  entering a cycle at POLICY_CHECK would mean resuming mid-policy-evaluation with the
  decision object no longer in hand — semantics the S7 table never defined; closing the
  cycle explicitly keeps the entry set tight ({PREFLIGHT, CLAUDE_RUNNING}, unchanged) and
  makes the journal's resting state a legal entry state. PREFLIGHT rather than IDLE
  because IDLE's only outbound trigger is the operator's `start_command`, already given
  for the run.
- DENY_AND_CONTINUE (loop.py): the refused forward closes the cycle and the run stops
  honestly with code `deny_and_continue` (machine NOT paused/halted, journal at
  PREFLIGHT, `deny_and_continue` note kept). It deliberately does NOT auto-retry the same
  instruction: there is nothing to send to the worker, and an auto-retry loop of a
  hard-denied prompt would burn provider calls; the operator decides whether to start
  again. DENY_AND_HALT is untouched (regression-tested).
- `CycleResult.continues` no longer includes POLICY_CHECK (narrowing = fail-closed
  direction); `run()` checks the shadow break before `continues` so
  `shadow_observation_complete` keeps its honest label.
- cli.py `cmd_start`: `_run_loop` wrapped in `except (LoopError, IllegalTransitionError)`
  — a refusal prints the report payload (`loop_refusal` with code/message plus an honesty
  note that `provider_calls_made` is not authoritative for a mid-run refusal; the audit
  log is), never a traceback. IllegalTransitionError is included because the state
  machine's blocking-state refusal (`assert_can_act`, e.g. PAUSED_RECOVERY) is the other
  uncaught crash of the same class — pilot run 2's exact symptom.
- Tests: `CycleCloseTests` (journal re-startable after a completed shadow cycle;
  DENY_AND_CONTINUE in supervised does not crash, reports `deny_and_continue`, journal
  resumable; DENY_AND_HALT still pauses hard);
  `CliStartTests::test_a_loop_refusal_is_a_report_not_a_traceback` (a stranded journal
  produces a named `bad_cycle_entry_state` report through the real CLI);
  `ShadowTests::test_shadow_never_reaches_forward_prompt` updated as described.

### F-4 — canonical S8.3 checkpoint-contract block in every dispatched unit prompt
- Runner level (`claude_runner.py`), so EVERY dispatched unit — the operator's first

## Risks / ambiguities (honest)

1. `deny_and_continue` is now a RUN stop code in both modes. Policy S4.4's
   "the run is not stopped" is honored in the sense that the machine is not
   paused/halted and the journal is immediately resumable; the alternative reading
   (auto-retry the same prompt) was rejected as an unbounded provider-call loop over a
   hard-denied instruction. Flagging in case the reviewer intended re-dispatch.
2. The F-4 contract is appended at the runner, AFTER the approval digest and the outbox
   `prompt_digest` are computed, so the exact bytes delivered to the CLI = journaled
   prompt + the supervisor-owned fixed contract block. The addition is deterministic,
   version-pinned supervisor text (recorded via `checkpoint_contract_appended` in the
   audit detail), but "prompt_digest = exact bytes sent" in the envelope docstring is now
   exact only up to that fixed suffix.
3. Two new S7 edges (`POLICY_CHECK->PREFLIGHT cycle_closed`,
   `CODEX_REVIEW->PAUSED_RECOVERY unsafe_condition`) — both add stop/close paths, neither
   weakens an existing refusal; no test pins the transition count.
4. `cmd_start` now also catches `IllegalTransitionError` around `_run_loop` (slightly
   beyond the literal "catch LoopError") because the blocking-state refusal is the same
   traceback class and is the F-2 run-2 symptom; every catch reports and never continues.
5. The replay corpus was NOT extended (no new historical cases; the corpus replays
   recorded policy decisions, which are unchanged).
6. `graceful_close_failed`-with-checkpoint and wall-during-grace remain flagged as
   distinct facts only in the loop reason strings; the runner still records `timed_out`
   for the rare wall-lapse-during-grace overlap (V-4 residual, see above).
