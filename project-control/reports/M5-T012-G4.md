The rework diff (`edc43f4f..aafc75fd`) touches only the test file (+105/-12) and the producer report
(+186/-1). I read it in full:

* The old `monkeypatch.setattr(socket, "socket", _no_socket)` — which starved Starlette's anyio
  blocking portal of the `socket.socketpair()` it needs for its own event-loop wakeup, hanging the
  suite forever — is **removed**.
* It is replaced by landmines at real egress choke points the portal never touches:
  `pluto_soda._OPENER`, `app.resilience.transport.DEFAULT_OPENER`,
  `http.client.HTTPConnection.connect`, `http.client.HTTPSConnection.connect`, and
  `socket.create_connection`. Each landmine **records** the attempt into `egress` as well as raising,
  so `assert egress == []` still fails if a connector swallows the raise into a typed transport error.
* The test additionally proves positively that the injected fixture fetcher and substrate were the
  only sources consulted (`sorted(set(consulted)) == ["pluto_fetcher", "spatial_substrate"]`), that
  the fixture transport really ran, and that no Socrata token exists or reaches an outbound header.
* **No papering over:** the rework adds no `sleep`, no pytest timeout, no retry, and no
  `setrecursionlimit` change. I grepped the diff for all of these; the fix is structural.

I did not take the "load-bearing" claim on faith. Read-only static check: `pluto_soda` binds
`_OPENER = DEFAULT_OPENER` (a `urllib.request.build_opener(NoRedirectHandler)`) and reads it **at call
time** inside `urllib_transport(...) -> _shared_urllib_transport(url, headers, timeout,
opener=_OPENER)` — so the patched name is genuinely the connector's outbound path, not a decorative
alias. Live check in a throwaway process (repo untouched): patching `_OPENER` with a recording
landmine and calling the connector's real `urllib_transport` produced
`raised: AssertionError egress attempted` and `landmine fired via _OPENER seam: ['opener.open']`.
The seam catches real egress.
