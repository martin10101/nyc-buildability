Why this is a G3 FAIL rather than an observation:
- It falsifies the producer report's closure claim, §2 BP-3: *"every typed refusal routes through `_validation_error` → `_bounded_message`"* and *"EVERY error path length-caps any embedded value"* (`project-control/reports/M5-T057-producer-report.md:74-79`). Scope of impact today is limited (internal, `INTERNAL_RULE_EVAL_ENABLED` off by default, ~1:1 byte amplification, no memory blowup) — this is a contract/precondition defect, not an availability exploit.

**In-scope fix** (single file, no seam edits): cap `field` in `_validation_error` (e.g. `body["field"] = _bounded_message(field)` or a tighter dedicated field cap), and/or add BP-2-style bounded-string validation for `lot.lot_line_segments[].id` / `lot.street_lines[].wall_id` in `_build_lot_context`.
