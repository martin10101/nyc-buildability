FINDINGS

[MEDIUM] M1 — disposition field is the un-covered weak link in the tamper-evidence chain (fail-safe residue).
The module docstring states MATCHED_OVERRIDE "is reached only by an unconditional row (disposition_when_located == matched_override)" (:26-28), and _validate_against_source only checks disposition ∈ {"indeterminate","matched_override"} (:146, :285). disposition_when_located is NOT digest-covered (it lives outside verbatim_excerpt) and its VALUE is never anchored to the source text. So a crafted snapshot that leaves verbatim_excerpt byte-identical (digest stays valid, quote-substring passes, row-field anchoring passes) but flips named_street_overrides.disposition_when_located from "indeterminate" to "matched_override" causes the two REAL rows (Broadway CD7, Allen St CD3) to return MATCHED_OVERRIDE — asserting a wide-street override without the "separated by mapped public park" predicate ever being verified, which is exactly the conservative refusal the design intends to guarantee.
Reproduced in-memory (read-only, no file writes): deep-copied the real packaged snapshot's raw, set disposition_when_located="matched_override", rebuilt the SectionSnapshot with the unchanged excerpt/digest → "digest still valid: True; tampered Broadway -> matched_override; GAP CONFIRMED: True". The shipped (untampered) snapshot returns indeterminate.
Acceptability: acceptable to SHIP for this DRAFT-marked, zero-consumer leaf module — the snapshot is repository-controlled package data (not runtime-attacker input), any edit is a reviewed commit, and no consumer acts on the output today. But the guard does NOT deliver its stated property ("a behavior-changing crafted snapshot cannot keep the digest valid"), so this MUST be closed before the wiring packet gives the module a consumer.
Remediation (code, not data): make the conservative refusal structural — refuse/override matched_override in _located() whenever the row carries an unresolved qualifier (qualifier_predicate_resolvable_from_text == false, or a non-empty qualifier_clause / open_legal_questions on the named block), so a row with an unverifiable predicate can never yield MATCHED_OVERRIDE regardless of the snapshot's disposition value. Alternatively bring disposition_when_located (and applicable_districts) under a structured digest so a value flip breaks integrity.

[LOW] L1 — construction does not validate block-level provision_id/section_anchor; a malformed-but-construction-passing snapshot raises KeyError at match() time instead of failing closed.
_build_rows (:243) and _validate_against_source (:269) never check the named block's provision_id/section_anchor, but _row_provenance (:340,:344), _located (:480) and match()'s bounds/degenerate branches (:404,:410) access self._named_block["provision_id"] / block["section_anchor"] directly. Reproduced: removing provision_id from the named block → construction OK, then match() on a located row raised KeyError('provision_id') — an exception escape, contrary to AS-3 ("never an exception … fail-closed to INDETERMINATE only"). Not exploitable with the shipped snapshot (keys present) and zero consumers, but harden by validating these keys at construction (fail closed to NamedStreetOverrideError) or using .get with an INDETERMINATE fallback.

[LOW] L2 — MatchResult.reason interpolates raw query strings with unbounded repr.
NOT_MATCHED/INDETERMINATE reasons echo query.street_name / query.borough / query.cross_street_* via !r with no length bound (:379, :391-393, :422-425). If wired to user-supplied input and the reason is logged, an attacker could inflate/log-inject via an oversized string. Impact is low (DRAFT, no network input today); when wired, bound these reprs (e.g. truncate to a fixed length).
