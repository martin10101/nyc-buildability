F-LOW-1 (ADVISORY) — GEOS wrap catches only GEOSException, not the ShapelyError family; docstrings overclaim. massing_model.py:176 (except GEOSException); docstrings :57-58 and :164/:169-170 ("no untyped error can escape").
- Empirical (shapely 2.0.7): TopologicalError / GeometryTypeError / DimensionError are ShapelyError subclasses but NOT GEOSException and NOT ValueError; a non-GEOS ShapelyError raised on a build path ESCAPES UNTYPED (probe: TopologicalError escaped raw).
- Reachability today ≈ zero: even an invalid bowtie's buffer/contains/centroid do not raise in 2.0.7 (probe #5); the realistic engine error (empty-centroid .x) is a GEOSException (caught). All inputs are finite/magnitude/NYC/simplicity-validated and the lot is is_valid-checked before shapely.
- Matters because the wrap's stated purpose is "map ONE exception family to a client response" and the docstring claims completeness; a future shapely/new op, or a route catching only MassingModelError, would 500 on TopologicalError/GeometryTypeError. Remediation (wiring packet, ~1 line): except ShapelyError (from shapely.errors import ShapelyError), or correct the docstrings to "any GEOSException". Spec DB-061(d) scoped it to GEOSException, so this is a refinement, not a spec violation.
