## 5. Findings (both LOW, non-blocking — route to the auth / public-exposure packet)

**F1 (LOW) — revoke leaks an existence oracle via the refusal message text, though the status oracle is closed.** `store.py:396-398` (id absent) and `:407-410` (id present but foreign) both raise `ConfirmationNotFoundError`, but with different messages; the route echoes `str(exc)` in the body (`site_definition.py:314`). So a foreign probe can distinguish "record exists elsewhere" ("…must belong to the property addressed by the request path") from "record does not exist" ("no site-definition confirmation exists for record id …"), even though the HTTP status (404) and `reject_code` (`confirmation_not_found`) are identical. The DB-040(a)-named 409-vs-404 status oracle is genuinely closed; this is a residual message-level existence oracle. Practical severity nil today (uuid4 ids, route unmounted/default-off/no-auth, GET already lists ids for an addressable condo). Suggest a uniform 404 message for both `ConfirmationNotFoundError` paths in revoke before auth lands.

**F2 (LOW) — revoke's healthy path binds on the LIVE condo_key, so a condo re-keying between create and revoke fails-closed against the human.** In the healthy branch `_matches_addressed_property` compares `record.condo_key == condo_key` where `condo_key` is the freshly-resolved key (`store.py:370-371`; route passes `_resolve_condo_key_best_effort`'s live key). If DOF re-keys the condo after create, the stored key ≠ the live key → `ConfirmationNotFoundError` → the human at the correct property cannot withdraw — the same D-051 wrong-direction class as the closed F-10, but reached via a healthy-but-drifted resolution rather than a degraded one (the addressed-BBL fallback only engages when the key is `None`). The named degraded classes (b) are all handled/tested; this drift edge is not. Since the addressed-BBL match already protects cross-property in the degraded branch, consider binding revoke purely on the stored condo_key / addressed-BBL (dropping the live-key equality) before mount. Non-blocking (unmounted, no calculation reads confirmations, block still surfaces honestly).
