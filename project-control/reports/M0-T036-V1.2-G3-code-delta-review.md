## Findings

**F-1 (BLOCKING, correctness/provenance): the V1.2.1 substitution never actuates the model change — no code path launches anything on claude-opus-4-8, while the first-class records claim it does.**
`_substitute_at_seam` (loop.py:938-985) sets `self._current_model = SUBSTITUTE_MODEL`, writes the durable `model_substitution` record and audit event, and "relaunches" — but the relaunched unit is dispatched through the SAME `ClaudeRunner` built once in `_run_loop` with `model=pinned_model, expected_model=pinned_model` (cli.py:1966-1970). `run_unit` builds argv from that frozen config (`build_argv(self.config)` claude_runner.py:756; `--model config.model` at claude_runner.py:176-177). Grep across the package confirms `_current_model` is consumed ONLY by journal/audit/record payloads; nothing ever writes the runner config, and there is no per-unit model parameter on `run_unit` (claude_runner.py:730-737).
Concrete failure scenario (once a real probe is wired): orchestrator-role seam hits quota_exhausted → `model_substitution` is journaled/audited asserting the session "relaunches EXPLICITLY on claude-opus-4-8" (loop.py:965, 969-981) → the next unit launches `claude --model <pinned Fable-5>` — the very model whose quota is exhausted → the unit fails → PAUSED_RECOVERY `no_valid_checkpoint`, with a durable-and-audited substitution record that is affirmatively false. If instead the provider silently served another model, `expected_model` is still the pin, so every substituted unit flags `model_mismatch` (claude_runner.py:932, 447) and re-arms rotation — the authorized substitution gets misclassified as a detected downgrade each cycle. Crash-resume compounds it: `_run_loop` rebuilds the runner on the pin unconditionally even when the loop's own resume logic re-derives an active substitution (loop.py:604-610 vs cli.py:1966-1970). The unit's own comment ("an EXPLICIT model selection on the relaunched runner config", loop.py:130-133) describes code that does not exist. Tests cannot see it: FakeRunner ignores models entirely.
Reachability today: none (F-2 — no probe wired), so no false record can currently be produced live and nothing can ever silently run on a substitute; the fail-closed direction survives, but by accident of the unwired probe. Same genus as the original review's V-1 (machinery present, actuation absent), aggravated by false first-class provenance — which is why it is BLOCKING rather than a note. Correction: relaunch through a runner configured `model=SUBSTITUTE_MODEL, expected_model=SUBSTITUTE_MODEL` while substituted (and back on return, and on resume with an active substitution), with a test asserting the relaunched unit's actual launch model/argv.
