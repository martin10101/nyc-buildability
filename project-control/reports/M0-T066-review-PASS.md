## Findings

**Observations (non-blocking):**
- **O-1 (Windows absolute-prefix validation gap, `tools/subsystem_resolver.py` `_validate_rule`):** empirically confirmed — a rule with `subsystem_id == prefix == "C:/Users"` passes all checks on Windows (`norm_path` leaves it unchanged; `Path(root) / "C:/Users"` → `C:\Users`; `is_dir()` True), admitting an out-of-tree vocabulary entry. Requires editing the committed, digest-stamped, reviewed map; Linux CI fails it closed; shipped map v1 is clean. Recommend rejecting prefixes where `PureWindowsPath(prefix).drive` is non-empty or resolved containment in `repo_root` fails.
- **O-2 (case-insensitive `is_dir` on Windows):** a wrong-case prefix (e.g. `Tools`) validates on Windows (confirmed `is_dir()` True) but fails closed on Linux CI; resolution matching itself is byte-exact so no mis-bucketing is possible. Same low exposure as O-1.
- **O-3 (`subsystem_entities.py:104`):** requirement→directive is derived from the directory name without checking `rid.startswith(did + "-R")`; a misfiled requirement id would silently link to the hosting directory's directive. Real registry scanned: zero mismatches; registry integrity is separately CI-enforced by `validate_directive_compliance.py`. A one-line consistency check would harden it.
- **O-4 (pass-1 discards invisible in output):** `propose()` drops malformed candidate shapes (non-string/non-dict, empty values) with no discard record in the result document. Accounting is complete at pass 2 (tested), but a `discarded_candidates` count would strengthen R046 auditability when a real LLM extractor feeds pass 1.
- **O-5 (duplicate evidence dropped):** `propose()` dedupes on `(kind,value)` keeping the first candidate's evidence; a duplicate's differing evidence reference is silently lost.
- **O-6 (non-string `kind` crash):** a dict candidate with e.g. `kind: 42` flows through `propose()` and can raise an unhandled `TypeError` in `sorted(out)` when mixed with string kinds — an ugly crash rather than a machine-readable refusal. The Unit D input contract should pin `kind` to strings (or `propose()` should coerce/refuse).
- **O-7 (count drift):** producer/coverage evidence says modularity selected "252 files"; I observed 254 (failures 0 in both — immaterial tree-state drift).
- **O-8 (undercount, not overclaim):** producer report says "7 machine-readable error codes"; the resolver actually defines 12 load/validation codes (5 in `_validate_rule` + 7 in `load_map`).
- **O-9 (dot-segment prefix):** `norm_path` strips only leading `./`, so a `tools/./x` prefix could validate if the directory exists; rejecting `.` segments alongside `..` would close it. Shipped map unaffected.
