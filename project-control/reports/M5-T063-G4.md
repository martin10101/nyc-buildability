## Findings

**C-1 (REQUIRED CORRECTION — test-adequacy + reachable behavior defect, AS-3 / DB-042(c)/HJ-3).**
The announcer substitution branch this packet introduced (`rule-evaluation.ts:530–543`) guards only on `entered_bbl` present + `analyzed_bbl` present + `analyzed_bbl !== entered_bbl`. The visible guard it is meant to mirror (`AnalysisIdentityNotice.tsx:54–61` `stampLegitimate`) additionally requires `entered_bbl === evaluated_input.bbl`. The announcer has `document.evaluated_input.bbl` in hand but does not apply that check.

Reachability (confirmed in source): the contract validator (`rule-evaluation-contract.ts:409` `checkSubstrateSubstitution`) is positive-shape only ("no legal or substitution meaning is judged here, only shape"), so `entered_bbl` may be any non-empty string. In `ArchitectEntry.tsx`, the announcer (line 78) is reached only when `identityEvaluation` is set, i.e. `evaluated_input.bbl === profile.identity.bbl`, and `AnalysisIdentityNotice` (line 174) renders the same document. So a shape-valid document with `evaluated_input.bbl = <opened BBL>` but `substrate_substitution.entered_bbl = <a different BBL>`, `analyzed_bbl = <another BBL>` produces:
- Visible: `stampLegitimate` false (entered_bbl ≠ requestedBbl) and `analyzedBbl === requestedBbl` → **nothing rendered**.
- Announcer: fires the substitution string → aria-live announces "analyzed on the recorded base tax lot {analyzed} for the condo billing lot {entered} **you entered** …".

A screen-reader user hears a substitution naming two BBLs shown nowhere and a **false "you entered" claim**, while the sighted user sees a normal evaluation with no substitution notice — a screen-reader/visible divergence, which is the exact HJ-3 anti-pattern this rider exists to close. The visible component has an explicit test for this document shape (`analysis-identity-substitution.test.tsx:142` "ignores a stamp whose entered_bbl disagrees with evaluated_input.bbl"); the announcer has no analog, so the divergence is both unimplemented and untested (the pack passes it).

Fix: in the announcer's substitution branch, also require `substitution.entered_bbl === document.evaluated_input.bbl` (mirroring the reproducible portion of `stampLegitimate`), so a non-corresponding stamp falls through to the generic classifier; add a mutation-sensitive test asserting that a stamp with `entered_bbl !== evaluated_input.bbl` announces the generic classifier string (not the substitution string). Route as this packet's rework (rule-evaluation.ts + rule-evaluation.test.ts are both in allowed_paths).
