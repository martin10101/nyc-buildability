## Findings

**G5-1 — scenario_label / proposal_id are unbounded (length) and uncharted (charset). Severity: LOW (advisory; BLOCKING precondition on B3).**
`check_proposal:699-703` requires only that `scenario_label` be a non-empty string; `proposal_id` (`:684`) is passed through entirely unvalidated (any string or None). Both are copied into every `CheckResult` (`:313,314` via `_result:628-630`) and the `ProposalCheckReport` (`:362,363`), and B3 will render them. Consequences at B3: (a) memory amplification (label copied into N results + report), bounded only by request-body limits; (b) reflected caller content into rendered output. No injection today (module never puts them in an exception/log/eval). File:line `proposal_checks.py:699-703, 684`. Remediation: at B3 cap length and restrict charset for `scenario_label`/`proposal_id` at the trust boundary and ensure the web layer escapes them.

**G5-2 — DoS worst case is bounded but large. Severity: LOW (advisory; BLOCKING precondition on B3).**
Worst-case work in the single `derive_proposal` call is dominated by wall × lot-line distance tests: `MAX_EXTERIOR_WALLS (4000, proposal.py:65) × MAX_LOT_LINE_SEGMENTS (1000)` = **4,000,000** `_segment_segment_distance` computations, plus `4000 × MAX_STREET_LINES (500)` = 2,000,000 street-line scans, plus level shoelace `MAX_LEVELS (500) × MAX_OUTLINE_VERTICES (1000)` = 500,000. This is a **product of independently-validated ceilings** — bounded, no unbounded/superlinear/exponential surface, no recursion, no regex (no ReDoS). The essential security property (bounded work, fail-closed) holds, so this is **acceptable for G5** as a pure library — matching the T048-G5 segment-test-count disposition. However 4M segment tests is a material single-request CPU cost (order tens of seconds in CPython at the ceiling). Remediation bound on B3 (BP-4): impose a wall-clock/CPU budget (or run off the request thread / in a bounded worker), or tighten the combined practical caps; the LotContext ceiling alone does not bound the product because walls come from the block's DB-013 ceiling.

**G5-3 — Propagated derivation/validator exception detail is not length-capped. Severity: LOW (advisory; out of B2 scope; BLOCKING precondition on B3).**
`check_proposal` documents (`:697-698`) that a derivation error propagates unchanged. `ProposalDerivationError` messages embed only finite numbers (short). But the block validator `proposal.py:243` (`f"... got {vertex!r}"`) can embed an uncapped repr for a malformed 2-element vertex containing a large element — this predates DB-034(b) and lives in a forbidden/byte-preserved path, so it is **not** a B2 defect. At B3 these strings become internet-facing. Remediation bound on B3 (BP-3): the route must length-cap any exception detail before serializing it into an HTTP response.

**G5-4 — Caller `lot_rule_facts` values reach the evaluator untyped; caller provenance/attestation mappings flow into rendered output. Severity: LOW (advisory; BLOCKING precondition on B3).**
`_build_rule_inputs:536-542` whitelists **keys** (only `CALLER_RULE_INPUT_NAMES` pass; others recorded as `unmapped`, never fed — good, no silent merge, AS-5 satisfied and tested `test_as5_declared_mapping_and_unmapped_facts:400`), but passes the **values** through unchecked (`inputs[key] = value`) into the existing (accepted, fail-closed) evaluator. Separately, caller-supplied `area_provenance`/`attestation` mappings are carried verbatim into `provided_provenance` (`derivation.py`, surfaced at `CheckResult:317`) which B3 renders. No injection in this module. Remediation bound on B3 (BP-5): validate `lot_rule_facts` value types/domains per the evaluator's input schema, and treat caller provenance/attestation as untrusted display data (escape on render).

**G5-5 — Process-global registry cache. Severity: INFO (benign).**
`_REGISTRY` singleton (`:729-737`) lazily loads production rulesets once. Holds only public legal-rule definitions — **no tenant data** — so it is not a cross-tenant leak vector. A first-call race between threads is benign (idempotent load, identical result). No action required.
