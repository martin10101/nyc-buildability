M5-T083 G1 — PART 3/3 — Findings (all ADVISORY; none BLOCKING) + verdict

F1 (ADVISORY) Clipping not modelled. W/W* AND form /BBox (§8.10.1 task c; BBox is Required) are not applied — surfaced geometry may include content a clip would remove. Consistent with the profile's documented no-clip stance for W/W* (:133), but the form-BBox non-clip is undocumented. Fix: state explicitly in _place_form/docstring that form BBox is not enforced (over-inclusion by design).

F2 (ADVISORY) Text advance not modelled. Spec (p.250) says text-showing ops advance Tm by glyph displacement; code never advances Tm (needs font metrics). Consequence beyond "nominal font_size": a 2nd Tj/TJ on the SAME line WITHOUT an intervening Td/Tm/T* is reported at the un-advanced anchor. Documented as "advance not modelled", but the POSITIONAL effect should be called out — anchors are exact only for the first show after each positioning op. Drawing-sheet labels (one positioned Tj each) are unaffected.

F3 (ADVISORY) q/Q and forms don't carry TEXT state. Text state (leading/font) IS graphics state (Table 52 p.121); code doesn't save/restore it on q/Q, and child forms start with font=None. Could over-refuse ("text before Tf") content relying on inherited state. Self-contained sheet forms unaffected.

F4 (ADVISORY) Bézier flatness bound — answer to the posed question. cubic_flat tests perpendicular distance of P1,P2 to the chord LINE (sheet_primitives:72-78). This IS a true, conservative bound on the curve's PERPENDICULAR deviation: projecting E(t)=b1·d1+b2·d2 onto the chord normal, the control points' along-chord offsets cancel (they sit at the ⅓/⅔ chord points), leaving |E·n|≤(3/4)·max(h1,h2)≤¾·tol. It is NOT a guaranteed bound on distance-to-SEGMENT when a control point projects outside [P0,P3] (along-chord overshoot: S-curves/cusps), nor at the depth-24 cap (:86). Midpoint de Casteljau subdivision itself is exact, and flattening is done in post-CTM user space (correct space for the declared tol). Docstring "conservative upper bound on the true curve deviation" is accurate for perpendicular error but slightly overstated generally — tighten to "perpendicular/cross-track".

F5 (ADVISORY) h/re/close then a segment op (l/c/v/y) WITHOUT an intervening m is refused (whole-doc), though Table 59 h says it should begin a new subpath. Conservative over-refusal; never wrong geometry. Rare.

F6 (ADVISORY) Mid-path CTM change edge case. If cm (or Q) changes the CTM BETWEEN path-construction ops in one open subpath, _curveto re-derives the curve start from the pre-CTM current point under the NEW CTM (:605) → wrong point. Pathological/malformed input; real generators set CTM before path build. Recommend refusing a CTM change while a subpath is open, or storing current point post-CTM.

F7 (ADVISORY) Inline images (BI/ID/EI) hit the unsupported-operator refusal (whole-doc). Safe (scan stops before binary data), but a sheet with an inline raster is wholly refused. Also /Rotate not applied and MediaBox recorded un-normalized (both fine given the "page default user space, later stage" contract; note for downstream).

Rationale: every implemented operator matches ISO 32000-1 in semantics/order/units; all deviations are documented simplifications or conservative refusals that never SILENTLY emit wrong geometry in the well-formed common case (CTM set before each path; labels individually positioned). The profile's contract explicitly scopes out clipping/advance and marks coordinates as page-user-space pending human unit/scale confirmation.
