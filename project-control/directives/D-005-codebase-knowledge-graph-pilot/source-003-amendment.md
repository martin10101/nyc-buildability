OWNER DECISION — M0-T030

I accept the M0-T030 owner packet recommendation as:

GO WITH CONDITIONS.

M0-T030 demonstrated a real correctness benefit, but it did NOT demonstrate reduced exploration/work. The benchmark showed graph-first improved correctness/completeness and reduced false claims, while using substantially more operations.

Therefore do NOT interpret this GO as authorization to make every Claude task "graph-first."

The graph is approved as ADVISORY NAVIGATION INFRASTRUCTURE, with selective use.

Proceed to propose/contract M0-T031 under the normal control plane, subject to the following owner clarification.

1. HARDENING

Include the small graph hardening items already identified by independent review, including at minimum:

- bind graph.json bytes to a cryptographic hash in metadata and verify it on load; corruption/tampering must cause regeneration/refusal, never silently serve altered cached graph;
- improve cache identity so separate same-named checkouts do not unnecessarily share one basename-only cache namespace;
- handle cache/meta read errors safely rather than exposing an avoidable traceback;
- preserve stdlib-only/no-network/no-hook/no-product-runtime-dependency architecture.

Do not expand this into a new graph platform.

2. SELECTIVE ROUTING, NOT UNIVERSAL GRAPH-FIRST

Do NOT require a graph query on every task.

The benchmark did not justify that.

Design the routing guidance so Claude uses ordinary direct navigation for simple/local questions and invokes the graph primarily where relationship knowledge provides material value.

Examples where graph use SHOULD be preferred:

- dependency/impact analysis;
- "who consumes X?";
- "what depends on X?";
- upstream/downstream questions;
- cross-layer traces;
- contract-change impact;
- unfamiliar subsystem orientation where dependencies are unclear;
- reviewer blast-radius analysis;
- multi-agent scoping where agents need bounded subsystem neighborhoods.

Examples where graph use should NOT be mandatory:

- known file opening;
- simple symbol lookup;
- tasks whose packet already names the exact relevant files;
- a question directly answered by authoritative committed documentation;
- small localized edits where ordinary search is clearly cheaper.

The intended decision model is:

TASK
  ↓
Is relationship/dependency discovery materially useful?
  ↓
YES → graph query → narrow candidates → authoritative source verification
NO  → normal direct navigation

3. TOKEN / WORK GOAL

Do not claim M0-T030 saves tokens or time. That was NOT demonstrated.

The proven benefit is currently:

- better correctness;
- better completeness;
- fewer false dependency/impact claims.

Future routing should attempt to preserve that accuracy gain WITHOUT imposing unnecessary graph/query/verification overhead on easy tasks.

Any later claim of token/time savings requires evidence.

4. AUTHORITATIVE SOURCE REMAINS FINAL

Graph output remains advisory.

For material conclusions, especially legal semantics, security, contracts, control-plane behavior, public interfaces, and dependency impact:

graph → likely locations → actual source verification.

Never graph → assumption.

5. AUTOMATIC FRESHNESS

Preserve the current fingerprint-based stale detection.

New indexed files or indexed configuration changes must be incorporated when the relevant working tree is next queried/regenerated.

Do not build a background watcher or Git hook.

6. BRANCH / WORKTREE MODEL

The graph should represent the source state of the checkout/worktree being queried, not attempt to combine every Git branch into one global graph.

Parallel branches may legitimately have different graph states.

7. SECURITY PIPELINE

Do not modify or replace the existing protected-main, PR, CI, secret-scan, dependency-policy, directive-compliance, or security-review processes.

The graph is navigation infrastructure only.

8. INITIAL INTEGRATION SURFACES

M0-T031 may implement only the minimal routing guidance already contemplated in the accepted decision packet, adjusted to SELECTIVE routing as stated above.

Do not implement:
- Mission Control Engineering Map;
- layer-B project/control graph;
- six-PRD expansion;
- NYC Evidence Knowledge Graph;
- Graphify;
- automatic Agent Teams graph injection beyond what is explicitly contracted.

Those remain separate owner decisions.

Return the M0-T031 packet for normal lifecycle handling.
