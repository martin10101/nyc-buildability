GO.

Proceed to author and execute one controlled task for the in-house code-navigation index generator + CI drift/freshness validation + 15–20-question navigation benchmark.

I agree with WAIT/REJECT for Graphify itself at this time. Do not install Graphify and do not reopen that decision during this task.

Before contracting the task, incorporate these owner clarifications:

1. GRAPH HONESTY

Do not overstate what a lightweight parser knows.

Python AST relationships may be richer than TypeScript relationships.

For every graph relationship, distinguish where appropriate between:
- exact/static
- derived
- partial
- unresolved

A TypeScript import edge may be authoritative syntactically; a caller/callee relationship must not be emitted as certain unless the implementation can actually establish it.

UNKNOWN/MISSING is preferable to an invented edge.

The V1 graph does NOT need perfect semantic caller/callee analysis to be useful.

2. DO NOT CREATE A SELF-REFERENTIAL SHA MODEL

Do not design graph freshness around embedding the final commit SHA into graph.json if graph.json itself is committed in that SHA.

Instead create a deterministic non-self-referential source identity/fingerprint over the exact canonical inputs used to generate the graph, explicitly excluding the generated graph artifact itself.

Record useful metadata such as:
- source/input fingerprint
- generator version
- generation mode
- included paths
- excluded paths
- base/orientation commit SHA where useful
- dirty/clean state where relevant

CI --check should recompute the source fingerprint/graph deterministically and detect drift.

Design this carefully before implementation.

3. EXCLUDE WORKTREE/CACHE POLLUTION

The index must not traverse duplicate/stale working copies or build artifacts.

Explicitly evaluate and exclude as applicable:
- .claude/worktrees/**
- .git/**
- node_modules/**
- .next/**
- build/dist/coverage/cache artifacts
- virtual environments
- other generated or duplicated trees

The 33 apparent orphaned .claude/worktrees husks discovered during D-005 are NOT authorized for deletion by this task.

Simply prevent them from polluting graph generation/search.

Any cleanup proposal is separate.

4. KEEP V1 SMALL

V1 should focus on useful CODE NAVIGATION relationships such as:
- file
- module
- class
- function/method
- import/export
- defined-in
- deterministic internal module dependency
- contract/schema touchpoints where reliably identifiable
- test relationships only where reliably derivable

Do not try to turn this V1 artifact into the future NYC Evidence Knowledge Graph.

Do not put properties, zoning rules, DOB filings, benchmarks, plans, solver runs, etc. into it.

Also do not yet create a giant combined project-control graph unless necessary for the benchmark.

5. TARGETED QUERYING

The agent should not load graph.json wholesale.

Provide a lightweight deterministic query interface, script, or equivalent that can answer bounded questions such as:
- find symbol
- show file/module
- upstream imports
- downstream importers
- neighbors
- contract references
- path between known nodes, if reliable
- impacted local neighborhood

Responses should be small and source-locatable.

6. SOURCE VERIFICATION REMAINS REQUIRED

Graph result → likely locations → read actual source.

The graph remains advisory navigation infrastructure, never authoritative truth.

This is especially mandatory for:
- legal semantics
- security
- control plane
- contracts
- dependency impact
- public interfaces
- acceptance/gate decisions

7. THE BENCHMARK IS LOAD-BEARING

Do not declare success based on node count, edge count, graph appearance, or generator completion.

Run the planned 15–20 representative questions with:
A. existing navigation workflow
B. graph-first workflow

Record observable evidence:
- searches/tool operations
- relevant files opened
- irrelevant files opened
- correctness
- completeness
- missed relationships
- false relationships
- elapsed time where reproducible/useful

Do not fabricate token counts.

A material correctness regression is a failure even if graph-first navigation is faster.

8. CI / PIPELINE

Prefer the repository's existing generator + --check pattern.

No Git hooks.
No Claude PreToolUse/PostToolUse hooks.
No global/user configuration.
No active-worktree mutation.
No runtime product dependency.

The navigation graph should be independently regenerable and CI-verifiable.

9. CURRENT DEVELOPMENT MUST CONTINUE

This infrastructure task must remain isolated from the currently active NYC Buildability product lanes.

Do not pause or rewrite unrelated M2/M3/M4/M5 work.

Respect existing worktree/confinement rules and current D-004 blockers.

- Claude session/task orientation
- targeted context routing

- Mission Control technical map later

Do not implement those downstream integrations merely because the generator passes.

Proceed through the normal controlled-task workflow, gates, PR and CI. Stop for owner decision before any broader pipeline integration.
